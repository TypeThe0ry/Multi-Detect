# OnboardAI：先学会核对当前画面

最终目标没有变：用户描述一次任务，无人机持续观察、判断和飞行，遇到变化能重新规划，
完成后带位置和证据返航。这里记录其中一次有明确范围的模型训练，不把它当成完整自主飞行。

## 为什么先做这一轮

上一轮预训练模型实际读了三维场景图像，却把被遮挡的目标说成一直可见，还在没有遥测时
说飞机没有移动。如果这种判断没有纠正，接上飞行执行只会放大错误。

本轮给模型两张真实图像：一张是先前看见目标时截取的可见 RGB 参考图，另一张是当前画面。
模型只回答“当前有可见证据”或“当前无法确认”。没有 GPS、NED 或运动遥测就保持未知。
“无法确认”不等于“目标不存在”，也不是一条飞行指令。

## 数据的实际范围

来源是仓库实体 SDF 场景的 Blender 离线三维渲染，不是这轮重新采集的 Gazebo 相机画面。
可见 mask 只在模型之外核对答案，模型读取的仍是 RGB；隐藏模型位置、世界坐标和遮挡计划
不进入模型输入。参考图从确实看见目标的像素中截取，不使用隐藏目标的假想轮廓。

| 分区 | 图文样本 | 独立视频段 | 可见 / 无法确认 |
| --- | ---: | ---: | ---: |
| 训练 | 26 | 2 | 18 / 8 |
| 验证 | 41 | 3 | 28 / 13 |
| 测试 | 43 | 3 | 30 / 13 |

原有整段视频分区不移动。10 个只剩模糊碎片的样本排除，不能强行标成目标不可见；还有一段
训练视频始终没有合格的可见参考，整段不进入训练。这是少量开发数据，不是通用识别、
身份恢复或多任务决策训练集。重复帧和成对比较不增加独立场景数量；测试分区也是已知的
开发渲染留出，不冒充全新盲测。

## 锁定的训练方式

在已运行的公开 Qwen3-VL-2B 模型上增加小型 LoRA，只更新语言注意力中的少量参数，原始
视觉和模型主体保持冻结。当前 r33 策略引用、原 COCO 检测器和飞控执行链不被替换。

先检查真实 forward/backward 是否有有限、非零梯度且显存足够；这一步不更新权重。
通过后固定训练一轮，只让训练分区进入优化器；验证和测试不参与权重更新或选 checkpoint。
仅监督回答部分，任务文本、图像 token 和补齐 token 不计算回答损失。

[预注册计划](../configs/training/onboard-vlm-grounding-lora-dev-v1.json)在模型输出之前锁定了
分区、可见性阈值、训练轮数、显存相关预算和比较方式；
[独立训练依赖](../requirements-vlm-grounding.txt)不升级旧训练环境。
ClusterYourCodex 的[算力预检](evidence/onboard-vlm-grounding-cluster-preflight-20261007-r1.json)
没有找到可用远程 CUDA 机器，转为本机 RTX 4060 8GB 检查，不把调度预检写成训练完成。

## 怎样判断有没有进步

原模型和训练后的候选必须读取完全相同的参考图、当前图和任务，保留未经修补的原始输出。
主要看可见目标和遮挡目标分别判对多少，不能用始终输出同一个答案或三个常量“unknown”
抬高准确率。错误目标 ID、虚构状态或非法 JSON 仍算失败。

同一参考图、同一任务下比较可见画面和完全遮挡画面，检查判断是否随实际像素变化。
这些成对检查来自同一视频，不当作额外独立样本。另记录时延、实际显存、可训练参数、
基座训练前后字节哈希，以及保存的 adapter 能否重新加载。

这一输入提供了明确参考裁剪，与上一轮八个 Prompt/历史用例不同，不能跨轮把答案差异
直接称为训练收益。时序记忆、未知任务、多目标和真正的飞行动作还需要各自的独立验证。

## 本轮实际结果（2026-10-07）

本机 RTX 4060 完成一轮、26 次真实 CUDA 参数更新，只训练了 802,816 个 LoRA 参数。
优化器峰值分配显存约 4.19 GiB，原模型及视觉主体的实际参数字节保持不变；adapter 已保存。
原模型和候选各生成 84 个未经修补的留出回答。结果需要分成两层看：

| 检查 | 原模型 | 训练后候选 |
| --- | ---: | ---: |
| 完整接口合格 | 1 / 84 | 73 / 84 |
| 完整接口及答案全部正确 | 1 / 84 | 61 / 84 |
| 严格接口可见性平衡准确率 | 0.86% | 67.44% |
| 仅诊断原始可见性字段的平衡准确率 | 72.48% | 79.05% |
| 完全遮挡画面正确保持“无法确认” | 22 / 26 | 16 / 26 |
| 复制正确的目标参考 ID | 84 / 84 | 73 / 84 |

原模型的 83 个接口失败都是遗漏三个未知字段，不是凭空编造 GPS。候选学会了补齐这些字段，
但在 11 个测试回答中写错目标 ID；原始可见性字段有所变化，却增加了遮挡误报。
字段诊断不放宽接口验收，也不能拿格式收益冒充同等幅度的视觉推理收益。
同任务、同参考而当前 RGB 不同的 250 组自然画面对照，字段判断两端都正确的组合
从 105 增至 138；它们复用上述 84 帧，不是 250 个独立实验或新生成。

训练过程和配对评估已经完成，但原生任务最终退出 **1**：保存 adapter 的重新加载校验
报参数字节不同。原始失败报告完整保留，不能把 26 次更新写成整个原生任务通过。
后续独立恢复检查实际退出 **0**：112 个保存的 FP32 张量与训练结束时完全一致，
固定验证样本的输入张量、生成 token 和原始回答均复现，基座前后哈希不变。
原因已用真实小模型复现：第二个 adapter 加载时先写入 BF16 再升回 FP32，丢失低位精度。
新入口先建立 FP32 adapter，再严格加载原张量，不通过修改保存值来掩盖差异。
它只做一次指定样本重放，优化器更新为 0，不改原失败报告，也不证明质量通过。
[恢复验证报告](../artifacts/evaluation/onboard-vlm-grounding-adapter-reload-20261007-r1/report.json)
与原报告分开登记；[独立入口](../scripts/verify_onboard_vlm_grounding_adapter.py)及 34 项回归
保留正确加载路径。冻结的原训练入口仍保留本轮源码身份，不把历史原生退出改成成功。
父模型回答平均 1.51 秒、候选平均 2.32 秒；输入／输出协议与前一轮八用例不同，
既不宣称跨轮加速，也不宣称已经满足实时飞行。

详细绑定、原生输出和独立复算见
[本轮训练证据](evidence/onboard-vlm-grounding-training-20261007-r1.json)。
**质量未通过，不晋升，不发飞控。** 训练损失下降不是自主任务或动作能力的证明。

## 仍然必须补什么

要让模型学会“为了任务往哪里飞”，还要在实体 Gazebo/PX4 中采集同步的图像、实测飞机状态、
实际执行动作、时间和完成记录。静态画面没有正确飞行动作答案，不能补造“往左十米”监督。
后续仍使用同一 OnboardAI 判断和规划执行路径；SIM 的通过不能替代 Jetson 性能、HIL/REAL、
室外 GPS 或最终发布验收。

下一步先增加独立三维场景、遮挡负样本和目标指代检查，再补多目标／任务记忆与实际执行
episode。不会用留出错误来反复挑这轮 checkpoint。未晋升候选，产品仍为 `0.3.0-pre.8`。
