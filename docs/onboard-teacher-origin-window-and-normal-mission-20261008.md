# 真实三维同期采集与正常 Mission 执行入口

本轮继续为 OnboardAI 的动作训练补真实反馈数据链。目标不变：用户描述任务后，AI 根据
实时画面、飞行状态和任务记忆选择下一步行动，执行后再次观察并调整。教师采集路线用于
取得经过审核的训练样本，不是最终用户任务的固定剧本。

## 这轮实际做了什么

三个子智能体并行实现同期采集、原始坐标重算、正常解锁执行入口；主线程整合、独立测试
并运行真实 PX4/Gazebo。本次不是 Python 轨迹夹具，也不是世界模型想象出来的视频。

新的实际采集成功退出，保存了：

- 4 帧 1280×960 的 Gazebo RGB，以及 4 份配对深度原始载荷。
- 5,819 条原始飞控消息，其中 5,705 条合法来源、114 条外来来源只记录，不进入判断。
- 37 次只读查询及 74 份完整原始输出：15 个参数前后各读一次、两个导航状态、四个预飞
  状态主题和一次实际加载场景导出。
- 同一个采集进程时钟、原始传感器时间、原始报文、投影及落盘时间，不改写为虚构同步。

没有孤立原包或队列溢出；队列峰值 44／512。两份 journal 均无未提交尾部。采集列明的
33 个来源在执行前后相同；监督器的另一个来源清单也相同。这是列明文件的检查，
不是完整依赖、操作系统或当前硬件的认证。实际容器已停止并删除，监督器的自有进程树
为空，未触发超时；独立 Docker 查询也确认该精确容器 ID 不存在。

## 地图与导航坐标分开验证

新的场景审计重新读取 Gazebo 导出的完整原件，不只相信仓库地图文件。实际加载的
15 个静态碰撞体与仓库定义的尺寸、位置、旋转和地理参考一致。动态飞机被明确排除；
这不证明机体包络、物理求解器接触、当前障碍变化或整条飞行路线已经获得许可。

导航审计独立检查原始 MAVLink 的 CRC、报文内容与 journal 切片，重算 RGB wire 的
头部与像素身份，并核对传感器时间、实际位姿、24 厘米机体安装偏移、HOME 和 EKF
参考点。两个实际导航 listener 的 host 区间覆盖四帧画面，但不宣称精确同时测量。

第一次导航审计失败的回执保留：原实现误将窗口开始前的 HOME 初始化变化，算作窗口内
变化。独立复查确认前四种 HOME 都早于导航窗口，窗口内 20 条 HOME 相同。新检查器
只比较窗口前最后的参考和窗口内消息，并另列窗口外变化；原包不删除，误差门不放宽。
GPS 原点建立时间保留原值，由两个同期 listener 核对其延续性，不假装它刚刚建立。

修正后的新 R2 对实际原件重算成功，45 份引用来源和四帧坐标链通过；两次 listener 与
原 LOCAL 报文的位置残差分别约 0.34／0.96 毫米，整条坐标链最大一致性残差约 12.9
厘米。这是本次软件 SIM 的来源一致性检查，不是物理定位精度、室外 GNSS 或精确同步
验收。唯一 GPS_GLOBAL_ORIGIN 报文早于窗口，其原接收时间没有被刷新。

封存文件只能证明那次窗口中的坐标关系。纯源审计不补造 Context、资源健康状态或当前
runtime attestation，始终返回 `origin_qualified=false` 和 `derived_origin=null`。
下一步仍需在运行中的新会话取得真正的实时上下文和资格，再执行净空及任务准入。

## 正常解锁执行入口已实现，尚未实际调用

新入口复用唯一通信线程和既有持久 Mission 事务。它要求已经完成上传、回读、提交和
一次性启动许可，才允许请求明确的 Mission 模式；确认新的模式和该模式的预飞健康状态
后，才请求正常解锁。ARM 的 force 参数为 0，不调用历史 force-arm 路径。命令意图先
保存，原始回复先落盘，再核对命令 ACK 和最新状态；API 返回不当成飞行成功。

返航中止也限定在本次已确认运行的 Mission，要求新的 ACK、返航模式、落地及解除解锁
状态。陈旧消息、外来来源、错误目标、状态变化、超时和来源漂移都拒绝；没有额外接收
循环、任意命令或自动生成的 PASS／Grant。本轮只有 CPU 协议验证，没有实际 ARM。

需要纠正此前的一个判断：`heading_good_for_control=false` 不单独表示禁止解锁。
固定固件的 `SYS_STATUS` 预飞健康位对应**当前模式**，不能把待命模式的通过用于 Mission。
见 [PX4 固定源码](https://raw.githubusercontent.com/PX4/PX4-Autopilot/83c4f4e580558816f0e398918f66358988004696/src/modules/mavlink/streams/SYS_STATUS.hpp)。
本次原始状态显示倾斜／航向对准完成、没有磁故障，当前模式预飞检查通过；
同时明确 `auto_mission_missing=true`。它不是 Mission 已获准启动的证据。

另一个区别也已核清：`SIM_GZ_EN_ODOM=1` 表示订阅模拟 odometry，不等于 EKF 正在融合
该来源。实际 `EKF2_EV_CTRL=0`，四种 EV aiding 关闭；不能为了符合旧假设把参数改成 0。
见 [PX4 参数定义](https://raw.githubusercontent.com/PX4/PX4-Autopilot/83c4f4e580558816f0e398918f66358988004696/src/modules/ekf2/params_external_vision.yaml)。

## 接下来怎样推进训练

最终 16 个文件的联合 CPU 回归共 602 项通过，13 个本轮源码／测试文件的 Ruff 和格式
检查通过。独立静态审查重新读取 226 个文件，检查全部 5,819 条 journal 切片、3,581
批双提交、74 份原始输出与四帧载荷，没有发现字节或计数不一致。它不重复声称新的
Docker／进程现场检查，不把保存深度 metadata 重建的 companion digest 当独立保存的头部。

1. 在新运行会话接好实时上下文重验证，分清计划时的绑定和发控制请求时的最新观测；
   原观测超过有效期就拒绝，不能刷新旧文件时间。
2. 取得实际原点、机体包络与完整路线净空，再走真正验证报告、持久事务和正常预飞检查。
3. 完成一次起飞、多动作段的有界教师飞行，保存实际命令、ACK、位姿、后继 RGB／深度
   以及失败恢复。计划位置不能当实际执行结果。
4. 审核完整架次后训练动作模型，比较公开底座、已有 adapter 和新候选；整场景留出，
   不把已用于调试的数据重称未见测试集。

公开候选及资源／许可限制仍见
[模型研究](onboard-pretrained-action-research-20261008-r3.md)。VLM 可以学习任务与视觉判断，
世界模型可以辅助研究，二者都不能替代真实执行反馈或授予飞行权限。

新模块是独立开发入口，没有变更默认 r33、旧 canonical 部署清单或 `0.3.0-pre.8`。
本轮没有新模型加载、优化器更新、模型晋升、实际飞行、Jetson／HIL／REAL／室外 GNSS
验收或最终发布。精确原件与源码绑定见
[本轮证据摘要](evidence/onboard-teacher-origin-window-and-normal-mission-20261008-r1.json)。
