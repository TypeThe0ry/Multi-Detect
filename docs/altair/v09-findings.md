## 结论
- 评测链（导出→规划/身份评测→门槛）已跑通。
- v0.9 训练集只有 3000 行（plan-sft-v4 1500 + r15-sft 1500），而 r21id-r3 用了约 22843 行身份数据；身份能力大幅退化（confirm_recall 近 0 说明模型倾向全部拒绝），规划 exact 也掉了。结论是数据量不够，不是配方（A/B/C 层集合）的问题。
- 固定翼在 b/c 上保持 1.0，说明合并训练没有破坏固定翼规划。

## v1 配方调整
1. 身份源用完整 r21id-r3 训练集（约 22843 行），不再用 1500 行子集。
2. 规划源用 r24 完整训练集（r24 1365 步×accumulation 4，约 5.5k 行）加固定翼新增样本。
3. 不再要求“精确比例且不过采样”：用 `build_dataset --total N` 固定总量，小源会重复（sample_id 加 #dupN）。建议比例：身份 ≥60%（≈22.8k 全量），规划 ≈20%，固定翼 ≈10%，真实视频 ≈5%，旧回放 ≈5%；总量约 38k 行。
4. 训练加 `--balance`（trainer 已有，把 confirm/approach/reject 过采样到不超过 2:1），防止 confirm_recall 塌缩；学习率沿用 r21id-r3 的配方而不是 1e-4（待确认其值，r24 用 2.5e-5）。
5. 先在 B 与 C 两个预设上各跑一次，比较身份退化程度，再决定主线。
6. 门槛不变：身份与规划不得低于现役，固定翼两类必须保持 1.0。
