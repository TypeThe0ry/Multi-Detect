# Altair v1.1 混编配方（真实世界数据 + 口径修复）

目标（用户 2026-11-14）：混编数据，提高精度和真实世界能力。
前提结论：v1-r1-a 与 r2-c 的失败证明身份指标随规划占比单调变差（规划梯度干扰身份判决），
且错误几乎全部是 confirm→approach。口径核对（md-scratch/altair-label-compare.md）显示：

- 评测 confirm 的候选框归一化面积中位 0.000425，训练 confirm 中位 0.000794，训练 approach 中位 0.000183；
  评测里的 confirm 明显偏小，处在训练里 approach 的尺寸范围边缘；
- confirm 与 approach 的距离中位数几乎相同（0.44 / 0.41），距离区分不了两类；
- 训练 true_target 的 visible_fraction 全是 null，评测没有 view_distance_m / visible_fraction。

结论：模型学到的是「目标小 → approach」的尺寸捷径，评测里小目标 confirm 就被判成 approach。
这是**数据口径问题**，不是训练超参问题，v1.1 先修数据再训。

## 1. 数据修复（先于一切训练）

1. **按目标尺寸分层平衡 confirm/approach。** 对 identity 源里 decision ∈ {confirm_target, approach_track}
   的行，按候选框归一化面积分 8 个分位箱（以两类合并后的分位切），每箱内把 confirm 与 approach 下采样到
   相同行数（取较少者）。目的是让「尺寸」对这两类没有预测力。reject、search_region、ask_clarify 不动。
2. **不伪造 visible_fraction。** 训练集该字段全 null，评测也没有，无法凭空补。
   凡由 SITL 真值能算出的（遮挡率、视距）只在**新采集**的 hover3/hover3p2/固定翼样本里写入；
   旧样本保持 null，训练 prompt 不使用这两个字段，避免模型把「字段是否缺失」当成信号。
3. **评测集补足小目标 confirm 对照。** 从新采集里按同样的尺寸分层，抽 held-out 的 confirm/approach 各一份，
   作为 `identity-size-matched` 附加评测（不替换原门槛评测，只报告）。
4. `collect_report.py` 增加身份混淆矩阵（confirm/approach/reject 三向）和按尺寸箱的 confirm_recall，
   后续每轮都看 approach 错误数，不只看汇总指标。

## 2. 混编来源与占比

| 来源 | 内容 | 占比目标 |
|---|---|---|
| identity-base | r21id-r3 身份集，经 1 修复 | 55% |
| identity-hover | hover3 / hover3p2 真实地形（rw_*）新采集，悬停下的身份判决 | 15% |
| identity-fw | 固定翼巡航与过渡（`--fw-cruise-observe`），身份与规划所需 FW 观测 | 10% |
| identity-real | 真实视频帧，Deneb 伪标签，只收抽检通过的（200 帧抽检 ≥0.9 的批次） | 15% |
| planning | r24 规划子采样 | ≤5%，或完全不混（见第 3 节） |

规则：
- 真实视频按**视频 id**切 train/val/test，同一视频不跨集（`--leak-scope` 之外另加视频级检查）。
- 每个新来源用 `--prefix-ids`，manifest 记录来源计数与 sha256。
- 新采集的 hover/FW 帧，场地优先精度更高的瑞士/荷兰，其次柏林/新加坡/深圳，再次美国 NAIP。
- 伪标签只收 Deneb 与人工抽检一致的批次；不通过的批次整批不进训练。
- 折叠尾座三角翼 + 云台视角优先：云台俯仰角变化的帧在 hover 与 FW 来源里不降采样。

## 3. 规划数据怎么处理（两条路，按 r2-d 结果二选一）

- **路线 M（单 adapter）**：r2-d（规划约 6%）若身份回到现役 ±0.01 内且规划不丢题，则 v1.1 单 adapter，规划占比 ≤5%。
- **路线 R（分任务 adapter + 路由）**：否则规划单独训一个 adapter，推理时由任务类型选择 LoRA
  （llama.cpp 多 LoRA 热切换）。两份 adapter 都只在各自任务数据上训，门槛评测按各自现役。
  代价写进结论：切换延迟、内存、部署复杂度；若代价过大再回到 M 的更小规划占比。

## 4. 训练配方（v1.1-a，身份主体）

- 预设 A（q/v r16/a32）热启动 r21id-r3 adapter；若混入新来源后身份指标上不去，再转预设 B/C 冷启动。
- lr 1e-5～1.5e-5，1 epoch，accum 4，`--crop-policy candidate_zoom_v2`。
- 不开整体 `--balance`（已有尺寸分层，整体平衡会把 approach 一起放大）。
- 规划占比为 0 的纯身份轮（v1.1-a）先跑，再按第 3 节加规划（v1.1-b）。

## 5. 验收

- 同一套 `eval_altair.py` 门槛，容差 0.01；固定翼两类保持 1.0；distractor_rejection ≥ 0.97 底线。
- 附加报告（不作为替代门槛）：size-matched confirm_recall、真实视频 held-out 帧的身份准确率、
  confirm/approach/reject 混淆矩阵。
- 任何一项关键指标低于现役则不替换，保持 r24 / r21id-r3 现役。

## 6. 依赖与排期

1. 等 r2-a / r2-b / r2-d 结果，决定路线 M 或 R；
2. 重采 pass1/pass2（hover3、hover3p2）和 FW 采集完成，转成 r15-sft 同格式身份行；
3. 真实视频帧 Deneb 伪标签抽检通过批次；
4. 实现 `scripts/altair/rebalance_decisions.py`（尺寸分层）并加进 build_dataset 流程，需要先确认 train.jsonl 的
   决策与候选框字段名（已向算力线程要样例行）；
5. 算力线程排 GPU 训练，不拖慢 SITL 采集超过 15%。
