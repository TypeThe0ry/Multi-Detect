# OnboardAI 已读到真实三维画面；下一步是学习导航动作

## 这轮实际做到了什么

RTX 4060 已用新接口完成一次 Qwen3-VL-2B 原生推理。输入不是预写的红车／绿车状态，
而是以前 Gazebo 城市场景真正保存的两帧相机像素、同源 GPS／姿态／速度和原任务：
“检查前方是否有可安全观察的目标”。原图、原报文与原时间保留，没有把旧图伪装成
当前正在飞行的图。完整原回答是 HOLD，飞行计划为空，没有发送飞控指令。

这证明了图像和部分传感器事实能进入同一次模型请求，不证明任务已经完成。原采集
架次的总报告仍是 failed；这次回放不能把原架次升级为自主飞行成功。

| 本次实测 | 结果 |
| --- | --- |
| 本机 GPU／模型 | RTX 4060 8GB／固定官方 Qwen3-VL-2B；不加载失败 LoRA |
| 原图 | 两帧 1280×960，相机像素总量 7,372,800 B |
| 模型实际处理 | 180,224 像素，小于 200,704 总预算 |
| Token／模型等待时间 | 输入 2,646，输出 156；9.015 秒 |
| 完整 worker 预热 | 32.032 秒；不以局部 load 指标代替冷启动 |
| 峰值 CUDA 分配／预留 | 约 5.37／5.47 GiB；不是整机内存或 Jetson 实测 |
| 原生进程／独立 CPU 审计 | 退出码均为 0 |
| 飞行／动作训练 | 均未执行 |

CPU 审计重新构建同一请求和官方处理器输入，消息、四个实际输入 tensor 的字节 hash、
真实图像 grid 和输出 token 解码都与原生记录一致；31 个绑定文件前后未改变。
它没有再次生成答案，也没有加载权重到 GPU。新增回放／审计入口联合 51 项软件测试
通过；封存后的证据／进度／parity 检查 54 项也通过，两组分开记录，不重复相加为任务
成功率。原生结果、CPU 审计和本轮源绑定回执分别保存，
上一阶段的回执不覆盖；更新前的六份文档也保留了精确快照。

## 现在还不能交给飞机的原因

这次回答的结构合法，但内容仍有问题。它断言“系统处于安全状态”，可输入中的 HOME、
模式、电量、风、净空和健康状态实际上未知；还把有限视野中的“未确认目标”说成
“不存在目标”。这些话不能当作安全判断、目标不存在的事实或合格训练标签。
0.95 是模型自己输出的置信度，不是经过标定的准确率。

9 秒级生成也不是可用的高速避障控制。最终模型负责根据任务与持续观察决定下一步，
飞控负责稳定控制；还需要实测状态、任务记忆、持续执行反馈和超时监督。未知输入
保持未知，不以补造状态换取非空飞行计划。

还有两个记录边界未解决：冻结 backend 的 kwargs 字典被官方处理器原地消费，原生
指标只保存了调用后的空字典；CPU 审计重建调用前预算并核对实际调用后值与 tensors，
没有篡改原指标。冻结 worker 的前处理异常仍只跨进程返回错误类型，失败路径没有
完整 grid／tensor 回执。回放 CLI 结束时枚举已有输出，枚举前外部删除文件的额外加固
仍待做；本次由主线程和审计器独立重开四个预期产物，实际没有缺失。

## 从“看图”走向“自主行动”

公开模型研究已找到 OpenFly、AeroVLA 和 TravelUAV 的导航权重／动作监督数据。
它们不是当前 Qwen 的可合并 adapter，也没有已核实的 Orin Nano 部署结果。
目前优先路线是审核 OpenFly 的 train 轨迹，在现有 Qwen 基座上增加独立动作训练，
不是继续只训练“画面里有什么”。[具体候选与来源](research/onboard-uav-action-model-candidates-20261007.md)。

训练前要逐步核对原任务、当前与过去图像、动作方向／幅度、姿态及来源。已发现官方
示例可能把未来帧当历史，论文／代码动作单位也不同，不能原样复制。没有真实时间间隔
的轨迹先学有序导航位移，不补秒数、不训练速度／动力学。外部 planned 动作不是本项目
PX4 已执行回执；STOP 不是 LAND，也不自动代表任务完成。
[下一轮 loader 与训练准入规格](research/onboard-action-training-admission-20261007.md)
把这些要求落到原轨迹、分区、动作标签与独立质量指标，仍不是已完成动作训练。

之后恢复可调度 Gazebo 运行环境，接通真正的“新画面／状态→模型动作→PX4执行→
后继画面／轨迹”。这才可以验证用户一次 Prompt 后持续搜索、确认、记录和返航，
不是让用户逐次选方向。世界模型用于历史表征／离线预测研究，不替代这个闭环。

默认 r33、原 COCO 检测器、SIM／REAL parity 和 `0.3.0-pre.8` 不变。
没有候选晋升、动作训练、Jetson、HIL／REAL、室外 GNSS 或最终 `0.3.0` 发布证据。
