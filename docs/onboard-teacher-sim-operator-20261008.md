# Gazebo 教师环境：地面观测已经合格，飞行和训练尚未通过

2026-10-08。本轮解决的是“训练环境是否能诚实提供飞控状态和画面”，
不是让旧固定剧本接替 AI。三个子智能体分别负责输入契约、SIM 操作员接口和独立审查；
root 完成接线、两次实际运行和证据整理。

## 实际取得的结果

第二次独立的一次性 PX4/Gazebo 运行退出 0。20 次地面观测尝试中，16 次通过原始来源、
接收时间、新鲜度、GPS、健康状态、未解锁、地面状态和当前 Hold 模式的 STANDBY 检查。
另外四次如实拒绝：一次九类输入未齐，两次早期飞控状态不合格，一次消息时间偏差过大。
这只表示运行期间的地面快照合格；容器关闭后，保存的快照不再是可用于控制的实时状态。

同场保存了 2 张 1280×960 RGB 和 2 份深度，来自实际三维场景相机；不是生成图、计划中的
位置或红车／绿车预设答案。保存 4,428 条原始遥测，其中 4,340 条为期望来源，88 条外来
消息仅记录、不参与本机判断。原包与可逆投影均封存，孤立原包和队列溢出为 0；独占接收
线程已退出、队列已排空。主机 Job 树与本轮 owned 容器清理完成。

本轮只在明确声明的一次性软件 SIM 中，将 `COM_RC_IN_MODE` 从 1 改成 4，并读回确认；
同时发出类型为 GCS 的心跳。不是修改真实飞控，也不是关闭所有安全检查。八项保护参数
前后相同，包含定位／健康／模式预飞检查和 RC／GCS 失联动作与超时。`COM_ARM_WO_GPS=1`
是本轮读到的继承配置，不是本轮放宽的设置；我们的观测入口仍要求合格 GPS。
心跳 22 次 API 返回只证明发送函数返回，不证明每一份网络报文独立交付。

## 为什么新增 Context v2

多旋翼在地面可能没有可用空速传感器，当前电池消息也没有剩余时间估计。旧“所有值必须是
数字”的约束会把合格的地面观测拒掉，或者诱导人填造数值。本轮新增独立版本，允许未知值，
并区别实际传感器、实际估计器和显式软件 SIM 模型来源；V1 映射没有被重解释。

v2 planner 能检查有来源的保守机型能力和预算，且不以地速冒充空速。SIM 能量／风模型不
允许进入 REAL 或 HIL 规划。但本轮实际快照的续航、空速、机型能力仍为空，camera、perception、
geofence 资源资格也没有被自动改为 true；它们不能直接生成可飞 Mission。
旧 38／40 维模型和现有 Mission 入口明确拒绝未经迁移的 v2，避免未知值静默进入旧模型。
这是版本隔离，不是固定搜索策略；任务方向和应变仍由 AI 学习。

## 首次失败与日志修复没有被覆盖

R1 使用普通 `px4-param show NAME`，真实退出码虽然是 0，但输出只有参数使用数量，
没有所需值。入口拒绝后未调用参数变更、未启动相机或接收会话。固定 PX4 提交的实现表明
普通 show 只遍历 used 参数；V2 使用精确名称的 `show -q NAME`，要求原 stdout 恰好为
一个有限数值。没有从元数据补默认值、全表回退或重试。[PX4 原实现](https://github.com/PX4/PX4-Autopilot/blob/83c4f4e580558816f0e398918f66358988004696/src/systemcmds/param/param.cpp#L640)。

R2 的 20 次操作员 native 调用全部退出 0，只有一次参数变更；随后 20 次只读诊断也退出 0。
日志采用逐字节有界读取：stdout 共观察 3,276,800 B、完整流哈希已记录，只保留原始前缀
131,072 B。没有把截断文件称为完整日志，超时和总输出上限仍会拒绝。

两次运行原件保持不变。R2 执行窗口内 61 项来源前后相同；结束后只调整了一个测试文件的
import 排序，并更新当前 parity／进度文档，不把新 parity 回填成旧运行已验证的身份。
本轮源文件与 retained-file audit 一致不等于重新运行过全部 SIM／HIL／REAL 发布矩阵。

独立只读审核另核过 499 个全文件和 554 个 offset-range 绑定，共散列 45,626,819 B；
这是字节身份核验，不是独立像素／深度解码或所有飞控包语义分析。当前只有 59／61 项
仍与运行时相同，两项已说明的运行后变化没有被抹掉；限定容器与两个 worker PID 当前不存在。
由于契约源码变化，软件 foundation 已实际重新执行并通过，旧源码哈希没有被伪改。
最终 458 项定向及 122 项文档／索引／回执回归共 580 个 CPU 测试通过，代码、格式、
源码 parity 和当前进度索引检查通过；这些验证不评价新模型或实际飞行能力。

## 接下来直接推进的训练路径

1. 将现有 owned-container 身份证明接到 v2 Mission 准入；明确运行域，不能只写 `SIM` 就取得控制权。
2. 建立可审计的 SIM 能量与保守机型能力预算；真实实测仍单独保留，缺值不能被估计值覆盖。
3. 证明 EKF／地图坐标原点、相机时钟、路线净空和教师输入资源。调用真实持久 Mission 事务，
   不让 fixture 自动 PASS／Grant 进入现场，也不绕过唯一的来源过滤接收者。
4. 在一次起飞内执行多个有限动作段，保存命令、ACK、实际姿态／位移以及动作后的 RGB／深度。
   要学习的是行动结果，不把计划坐标当实际移动，不把生成视频当专家轨迹。
5. 审核新三维数据后，比较公开底座、已有 adapter 和候选；按整场景留出测试任务理解、
   左右／升降／多尺度移动、受阻恢复、返航和汇报。质量失败保留，不能只靠 loss 低就晋升。

必须各自验证。本轮没有下载新权重或接受门控条款，当前 r33 默认模型与 `0.3.0-pre.8` 不变。
