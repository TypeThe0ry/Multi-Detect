# 真实 Gazebo 教师观察：先把画面与行动证据接通

目标不是继续写红车／绿车的固定脚本，而是取得真正的三维画面、姿态、飞控状态和行动
反馈，让同一套 OnboardAI 能学会“看见什么、下一步怎样飞、飞完有什么变化”。本页
记录当前最短前置阶段：观察真实模拟器，尚不执行教师飞行，也不训练模型。

后续[只读PX4诊断](onboard-teacher-px4-diagnostics-20261008.md)现已保存真实版本和17个
参数；R3原UNKNOWN事件另行CRC及metadata匹配。新回合日志超限仍失败，旧R1／R2／R3
原件与原状态不改，下文R3“尚未解码／未定因”是该回合当时的结果，不冒当前预飞通过。

## 最新真实结果：V3 并行采集已运行，待命资格仍拒绝

[R3 证据摘要](evidence/onboard-teacher-gazebo-observation-20261008-r3.json)记录第三次真实
PX4/Gazebo 回合：三次独立有限相机窗口，各取得两张 1280×960 RGB 与配对深度；
5,943 条原包完整提交，5,827 条来源 ID 接受、116 条仅保留，0 orphan。背景接收与
主线程日志写入同期运行，队列最高 67／256，最终为零，接收和相机线程均退出。

V3 每批最多 16 条：先同步原包 journal，再同步可逆投影 journal，两份完成前不更新
最新消息。1,504 批各完成两次提交；只对选中的九类消息生成旧桥兼容文件，记录原始
接收时间、journal offsets 与摘要，不靠再次写文件续命。57 份实际快照与 60 次资格
尝试分别保留，最后九类消息均在原来的两秒门内，旧 R1／R2 源码与原件未改。

独立统计显示处理速率约 189.68 条／秒，上轮约 25.81；中位 receive→projection-ready
延迟为 10.08ms，上轮为 36.43ms。但 P95 为 223.39ms，比上轮的 45.99ms 更差：
批量快照仍会暂停 writer，吞吐改善不等于尾延迟或实时推理验收通过。统计不能把全部
服务耗时归因于单次 fsync，也不证明两个回合的场景进度或传感器时间严格等价。

整轮仍 `context-refused`，root／child native 1，程序原 error 为 null。资格尝试中
3 次输入未齐、12 次时间跨度超过一秒、45 次拒绝“并非实际 STANDBY”。23 条实际
HEARTBEAT 都报告状态 0，没有待命状态 3；未确认具体预飞失败原因。电池继续原样
保留 `time_remaining=0`、`current_battery=-1`，空速为 NaN，不把这些未知值改成有效。
实际 installed pymavlink 2.4.50 的 common／development 均没有 410／411 定义；24 个
原包离线解析仍是 UNKNOWN，且未知 ID 在 CRC 检查前就返回，不冒称 CRC 已验证。
下一步需用当前固定固件的定义离线解释原包，
并只读查询真实参数与预飞状态；不能改参数关闭检查或把 UNINIT 当成允许起飞。

三个相机 helper 原生退出均为 0；容器 launch／stop／rm 原生 0、最终 inspect 确认
不存在；owned Job 为空，无 watchdog，26 个代码／环境／产品保护来源前后不变。
108 项新增 CPU 测试与旧相关回归合计 366 项通过，软件成绩与这次实际采集分开。
独立链审计另核 1,136 个文件／94,606,302B：全部原包及 typed 投影、57 份快照和
51,609,600B 原 RGB／深度均通过。该范围不包含 resources sidecar 与 owned Job
收尾文件，不能称整个目录每个文件都独立审过；容器／进程原生终态另由监督报告证明。
没有 Mission、ARM、模型加载、新训练、晋升、硬件验收或最终版本发布。

## R2 原结果：画面与原包已保存，仍不批准飞行

[R2 证据摘要](evidence/onboard-teacher-gazebo-observation-20261008-r2.json)记录新版采集的
实际结果：2 张 1280×960 RGB、2 份配对 FLOAT32 深度、1,057 条原始遥测；其中 1,033
条通过来源 ID 过滤，24 条只保留原序，不进入合法缓存。没有 orphan 或类型转换丢包。
这 24 条均是 decoder 未识别类别：原包 header 为 1／1，但 decoder 来源接口返回
0／0，所以按非准入处理；`foreign` 计数不证明它们来自另一架飞行器。
11 次遥测请求仅代表 API 已调用，保存窗口内没有 ACK，不能声称已确认网络交付。

但整轮仍是 `context-refused`，root／child native 1，不是自主飞行通过。最后一次快照
尝试因消息接收时间跨度超限被拒；截止时只有 4／9 类必需消息满足 2 秒新鲜度，10 秒
诊断窗口有 7／9 类。HOME 与 BATTERY 并非完全没收到，各原序保存一次，之后已陈旧。
保存的电池报告剩余百分比 99、`time_remaining=0`（没有可用的剩余时间估计）；VFR
空速为原始 NaN 位模式。后两项是额外原件诊断，不冒充原报告中唯一的拒绝原因。

独立逐条复算还发现：三次实际资格尝试的时间跨度分别为 0.664／1.097／1.482 秒，
第一次能过时间门，但当时画面已经超过 12 秒；三条 HEARTBEAT 均仍报告状态 0，而非
所需的待命状态。GPS 原包是 fix 3／10 星／水平精度 900mm，不应把所有失败泛称为
“GPS 不好”。源 boot 时间只推进 3.116 秒，而相应接收区间超过 40 秒，说明不能用
新的接收时刻冒充新的传感器数据；这些量测尚不能精确区分网络积压与慢模拟器。

原始资料共核验 4,228 个遥测文件／3,194,071B，两个原始相机包分别绑定 RGB 与深度
摘要。相机 helper native 0；容器启动／stop／rm 均为 0，最终缺失确认，owned Job
为空，无 watchdog 触发。19 个代码／运行环境／产品保护来源前后身份相同。

新增 V2 记录器 81 项与观察入口 9 项，连同原会话、快照和集成共 258 项定向 CPU
测试通过；软件测试与上述真实采集各自记账。没有加载新模型、训练更新或飞行发送。

实际第一帧另导出不缩放、不加标记的无损 PNG 预览；逐像素与原 BGR24 解码一致。
它是地面出生视角的粗几何场景，不是高保真场景或空中教师轨迹，不足以作导航训练。

## 应推翻的实现限制，以及仍需保留的真实约束

- 原包、来源和时间不能造假；陈旧消息、NaN、未知续航、未验证原点不能被改成有效
  输入。这些仍需保留。传感器自己的时间与 host 接收时刻必须分开。
- “每个原包四个文件、四次同步落盘”和“相机结束后才继续接收遥测”只是实现方式。
  实测 receive→dispatch 中位 36.43ms、P95 45.99ms，串行处理约 25.81 条／秒，
  95% 以上记录区间耗在该服务路径。不能把整个耗时全部归因于某个 fsync 系统调用，
  也不能因此推定请求交付失败，但这条路径显然不适合作为实时高吞吐采集器。
- “任何机型必须报告有效空速”也不是物理约束。多旋翼没有空速传感器时，应保留
  “无此测量”的状态，并让确实需要空速的任务拒绝；不能偷偷用地速或零代替空速。
  当前旧桥仍要求有限空速，机型相关接口扩展尚未实现。

因此下一版优先改采集结构：有界批次先提交原包 journal，再提交可逆投影 journal；
两份落盘前不更新合法缓存。只对被选中的最新九类消息生成兼容证据文件，保留原始
接收时刻，不通过重新写文件续命。相机与唯一遥测接收者并行，队列过载和部分写失败
明确拒绝，不放宽原来的 GPS／时间门。该 V3 设计现已实现并运行，实测结果见本页顶部。
必须显式重建 receive-owner／有界队列或非阻塞事件循环，不能把目前有线程归属门的
`raw_receive` 直接塞入后台线程。资格窗口还需取得新画面，并保存每次具体拒绝原因，
不只保留末次错误。新回合实际验证批次提交、持续接收和吞吐改善，但尾延迟仍未通过。

## 本轮已实现（R1 阶段）

三个子智能体并行实现／审核，主线程集成并运行：

- 独立、单次 owned PX4/Gazebo 会话，限定本地隔离端口与固定镜像，只清理核实属于
  本次运行的容器；没有全局清理或关闭用户程序。
- 只有一个原始 MAVLink 接收者，先保存原包与来源，再更新合法来源的数据。首次合法
  HEARTBEAT 持久化后才请求遥测；API 调用、回执和真正的网络交付分开记录。
- 从真实消息构建已落盘、来源可核查的观察快照；未知 GPS 精度、续航或错误状态拒绝。
  配置风不称实测风，未完成净空或模型加载的资源保留 false。
- 二次检查慢写入后的观测年龄；封存／清理失败不掩盖原错误。原点、源时间与 host
  时间仍分开，不把同一个时钟名称或零坐标当已完成映射。

最终 168 项定向 CPU 夹具通过（`6f8bf4`／native 0），包含实际记录器到实际快照桥的
集成。它们不是外部模拟飞行证据。

## 首次真实运行结果：失败如实保留

[R1 证据摘要](evidence/onboard-teacher-gazebo-observation-20261008-r1.json)绑定完整原始
报告。实际启动了固定摘要的 PX4/Gazebo 容器，收到并保存一个合法来源的 COMMAND_LONG
原包（41B）。接下来原 JSON 记录器拒绝 `document.data` 的非 JSON 类型，尚未获得
合法 HEARTBEAT、相机帧或续航包，因此不存在“实测剩余续航是零”的证据。

父进程及子进程 native exit 均为 1；自有 Windows Job 进程树空，无 watchdog 触发，
12 个源文件／受保护文件运行前后逐字节身份相同。容器 stop／rm 原生退出 0，最终
inspect 确认缺失。此次没有飞行、模型推理或训练。

旧记录器在 JSON 转换之前没有保存失败包，故无法确定该实际报文的具体类别或数据
类型。只读消息库检查能复现 bytearray 等类型的同类错误，不能把复现类型当原始事实。
R1 源码和失败原件已封存；新版本单独支持可逆类型编码，并先保存原包。

## 接下来怎样成为真正的训练数据

1. R3 已运行批量日志与并行采集；先查真实预飞状态及参数，降低快照尾延迟，完整迁移
   机型测量有效性和有来源的 SIM 能量预算。多旋翼不能被迫报告不存在的空速传感器，
   固定翼真正依赖空速的检查也不能放松；未知电流和续航不变成零值或默认常数。
2. 核查实际 x500 碰撞／旋翼包络、SDF 全路径扫掠、Gazebo 与 PX4 原点／姿态映射。
   出生区近处的三维短路线目前只是候选，不是已通过的飞行航线。
3. 同一持久 Mission 事务完成 upload／readback／commit／permit，正常解锁，不用
   VTOL force-arm 或测试自动 PASS／grant。记录多个真实平移、升降、转向及停留段。
4. 将画面与实际执行结果对齐、审核专家标签，划开训练与未见任务／场景，再训练现有
   OnboardAI；必要时做独立小型 VLA 对照。只有导航质量和实际资源验证都通过，才能
   替换默认模型并继续 Jetson／HIL／REAL。

这条教师采集路线是训练数据工具，不是最终在线 AI 的固定决策规则。默认 r33、
`0.3.0-pre.8`、发布 parity 及最终发布门均未改变。
