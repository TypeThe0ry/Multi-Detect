# 慢模型 r16 结果（2026-10-18）

结论：**不替换 r12**，但找到了 r15、r16 共同退步的根因并已修复，r17 按修复后的数据重训（排在三角化对照补飞之后自动运行）。

## 这一轮做了什么

- 补采易混物视角：在 r15 的 20 个世界里，让专家教师专门飞向场地里的易混物体（任务文字仍是找真目标），80 个架次完成 77 个（`--teacher-target confuser`）。
- 修好 r15 的候选框缓存路径后，真实候选框样本这次用上了：真目标 124、干扰物 681、反事实 626、背景 9。
- 新增训练行 3,203（r15 只有 1,085），合并 r12 的 25% 回放后共 4,933 行，正样本占比 0.410（r12 0.400）。
- 从 r12 热启动，1 个 epoch，约 1,233 步、58 分钟。

## 退步全部来自一对类别

把 v1 的错误按世界拆开：r16 比 r12 多出的 212 次误接受里，**204 次是同一个场景**——测试世界 gen_v2_w0037，任务“找皮卡”，候选是一辆 SUV。

| v1 干扰物拒绝 | r12 | r15 | r16 |
|---|---:|---:|---:|
| gen_v2_w0037（找皮卡、看到 SUV，226 行） | 98.7% | 8.0% | 8.0% |
| 其余所有世界（803 行） | 93.9% | 91.3% | **96.5%** |

除了“皮卡 vs SUV”，r16 在真实飞行集上已经比 r12 更会拒绝干扰物。

## 根因（两个问题叠在一起）

1. **反事实样本只教“是”。** 为了让模型按任务文字判断，建集时会把任务改写成“找画面里的某个干扰物”并标为确认。但从来没有配对的“任务说找 X、候选是 Y → 拒绝”。训练集里所有“找皮卡”的行全是确认，模型于是学成“任务说找某种车，看到车就说是”。
2. **测试集的留出类别漏进了训练。** v1/v3 用的 generated-v2 测试世界故意把 SUV、皮卡、停车牌、邮筒、行人留作“训练中从没当过目标”的类别；r15 新生成的世界索引里留出列表是空的，其中一个世界的目标就是 SUV，另一些世界里皮卡被反事实改写成了目标。

数据标注本身是对的（抽查画面，标成皮卡的确实是皮卡）。

v3 的提升不是泄漏造成的：去掉 SUV / 皮卡两个测试世界后，r16 在其余 v3 世界上 115/119，r12 97/119。

## 修复（`d228ee9`）

- 每条反事实“是”配一条“否”：同一画面里另一个任务文字不描述的物体（优先真目标，永远不用留出类别），且这些行在负样本抽样时全部保留。
- 新参数 `--holdout-from`：把另一份索引（默认 generated-v2）的留出类别也当作留出，目标是留出类别的训练世界整段跳过。
- r15/r16 这类补采轮次的流水线默认带上这两项。
