# SITL 队列：按候选槽位保留公平性

旧公平队列只按全局票序与当前请求可见的free_count放行。当泛用作业只能申请0–2且三槽
都忙时，它的早票会阻挡后面专用slot4的三角翼作业，即使slot4完全空闲。

修复保留现有owner首行和票名priority/FIFO排序，在新票据第二行声明配置候选范围及
指定槽位。检查每一个实际候选slot时，只受更早且可能竞争该slot的票据阻挡；未知、
格式不完整的旧票据仍保守视为能竞争所有slot，绝不通过猜测旧作业用途绕过。
单槽客户端使用全局unsuffixed锁，因此也按全局竞争处理。锁目录mkdir仍是跨进程
最终原子互斥；未改全局锁路径、端口、超时、心跳或stale owner宽限。

同时修复非阻塞获取失败后的票据清理：mkdir竞争输家不遗留活票，失败的锁实例可以
重新排队。不会删除竞争赢家的目录或owner。

验证日志均在运行区：
- `runs/sitl-slot-aware-red-20261108.out`：旧代码真实临时锁复现0/1/2已持有、泛用早票
  等待时，空闲4获取失败。只使用测试临时目录，没有修改真实共享队列。
- `runs/sitl-slot-aware-green-20261108.out`：25项相关测试通过；包括跨进程唯一槽位、
  重叠priority/FIFO、不竞争槽位改选、旧/坏票据、stale owner/ticket、mkdir竞争清理。
- `runs/sitl-slot-aware-gate-20261108.out`：独立CPU onboard gate PASS（80秒）。
  首次运行因新工作树缺少共享artifacts输入而失败；补软链后完整重跑通过。

运行中的旧进程不会热更新import，也没有改写它们的票据；旧票据造成的保守等待仍
可能持续到它正常取得/释放锁。新作业才会受益，不能把本次单测通过说成现有三角翼
飞行门禁已经恢复或通过。
