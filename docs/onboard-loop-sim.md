# SIM 机载自主搜索闭环

目标：飞机只拿到一句任务文字（例如“找到皮卡车并记录位置”），在 Gazebo + PX4 SITL 里自己搜索、接近、确认、记录位置并返航；全程不读场景真值，真值只在飞完后用于打分。

## 组成

| 层 | 实现 | 作用 |
| --- | --- | --- |
| 快系统 | 微调 YOLOE-11s（`artifacts/experiments/yoloe-v2-r3-seg-drop-full`），20 个通用词，置信度 0.05，1280 输入 | 只出候选框，类别标签不用；对没训练过的类也能出框（已见类召回 99.1%，未见类 66.9%） |
| 慢系统 | Qwen3-VL-2B LoRA 合并后 GGUF Q5_K_M，llama.cpp `llama-server` | 对单个候选（放大裁剪 + 焦点轨迹）判断“是不是任务要找的东西”：`confirm_target` / `approach_track` / `reject_track` |
| 主机闭环 | `src/multidetect/autonomy/onboard_loop.py`（纯逻辑，无 I/O） | 跟踪、决定问慢系统哪个候选、接近 / 确认 / 返航，输出有界动作原语 |
| 策略胶水 | `scripts/onboard_policy.py` | 读图、跑 YOLOE、调慢系统、算地面点，交给主机闭环 |
| 采集器 | `scripts/collect_sim_teacher_episodes.py --teacher onboard` | 起容器、MAVLink、帧服务器、执行动作并记录每步 |
| 评测 | `scripts/eval_onboard_loop_campaign.py` + `scripts/score_onboard_loop.py` | 逐测试世界飞、按真值打分 |

搜索航线复用专家教师的“扩展方形”航线，但把目标放在一千万米外，所以航线本身不知道目标在哪；障碍物检查只用静态地图。

## 主机闭环怎么决定

1. **跟踪**：每个候选框按框底中心反投影到地面（完整姿态 + 相机安装角，`pixel_ground_point`），按地面距离关联（门限 max(4 m, 15% 距离)）；没有地面点时按实测偏航变化在俯视相机上旋转预测像素位置。
2. **问慢系统**：没判过的、判决过期（12 步）的、以及正在接近的焦点每个新视角都问；框短边 < 10 px 不问；每步最多 3 次。
3. **判决分级**：`approach_track` 只用于转向接近，不算确认票；`confirm_target` 才算一票；`reject_track` 清空票数。
4. **接近**：先转向，再飞有界的一段（3–15 m），地图允许时边飞边下降（最低 8 m）。每段步长会被限制，保证目标仍在画面下沿以上（留 1.25 倍余量）；太近但还高于最低高度就原地下降，否则停在“最近可视位置”。
5. **确认**：框没贴边，并且满足：两个视角都投了 `confirm_target`；或一票且（框不再变大 / 已在正上方 / 已在最近可视位置）。确认后记录框底中心的地面坐标。
6. **放弃**：同一个焦点接近 8 步仍没有一票确认就放弃，回到搜索；焦点短暂丢失（≤ 4 步）时继续飞向它记住的地面位置。
7. **返航**：先爬回巡航高度，再转向回家、悬停结束。

## 打分

`score_onboard_loop.py`：确认的位置距真目标 ≤ 10 m，且确认的框与真目标分割框 IoU ≥ 0.1，才算成功；确认了别的东西算误确认。另外记录步数、慢系统调用次数、飞行距离和确认规则。

| --- | --- | --- | --- | --- |
| r2-seg 慢模型，无下降（仅 w0034–36） | 1/6 | 0 | 5/6 | — |
| r3-seg 慢模型 + 下降 | 2/12 | 1/12 | 9/12 | 2.36 m |
| + 地面锚定轨迹、保持在视野内 | 5/12（按任务语义 7/12） | 4/12（其中 2 次为任务歧义） | 3/12 | 2.41 m |

| + 慢模型 v2-r4-prop（真实候选难例、身份约束解码） | **6/12（按任务语义 8/12）** | 4/12（其中 2 次为任务歧义） | 2/12 | **0.57 m** |

r3-seg + 下降这一轮的逐世界分析：

- **w0034 停车标志 0/2**：27 m 巡航高度下标志最多 4 px，检测器从没出框。需要更低的搜索高度或变焦。
- **w0035 SUV 2/2**：定位误差 2.36 m、0.68 m，框 IoU 0.93 / 0.97。
- **w0036 行人 0/2**：慢模型多次投 `confirm_target`，但每次转向后轨迹 ID 断开、票数清零。原因是旧的自运动补偿只做水平平移，而下视相机偏航时点会上下移动，且指令偏航和实际偏航差到 13°。
- **w0037 皮卡 0/2**：一次把 85 m 外的 SUV 连判 5 次“皮卡”而误确认（慢模型身份错误）；另一次在皮卡和 SUV 之间左右摆了 80 步，同样是轨迹 ID 断开导致的焦点来回切换。
- **w0038 邮筒 0/2**：9 m 外已投一票，下一段前进加下降让邮筒滑出画面下沿，再也没看到（飞过头）。
- **w0039 行人 0/2**：和 w0036 相同，转向后丢轨迹。

加入地面锚定轨迹和“保持在视野内”之后（`eval-v2-test-r3seg-worldtracks`）：

- **w0035 SUV 2/2**、**w0038 邮筒 2/2**（定位误差 0.48 m、0.31 m，13–16 步完成）、**w0036 行人 1/2**（同一条轨迹连拿两票确认）。
- **w0037 皮卡 0/2，两次都误确认了 SUV**：跟踪和接近已经正常，是慢模型在 31 m、15 m 近处仍把 SUV 判成皮卡。测试集目标类别训练时从没当过目标，这是慢模型在未见类别上分不清相近车型。
- **w0039 行人 0/2，两次都确认了另一个人**：任务是“找到人”，世界里还有一个“女性行人”干扰物，飞机确认的对象同样符合任务文字。打分器把这种情况单独标为 `task_equivalent`，严格成功率不算它。
- w0036 另一次失败暴露了“焦点在画面里被拒绝后仍按短暂丢失悬停”的问题，已修复（`7c1aaa7`）。

**任务歧义**：世界生成器会故意放同类干扰物，但任务文字只用目标的第一个类别词和颜色，因此 w0009、w0022（训练）和 w0036、w0039（测试）里干扰物同样满足任务文字；训练世界里这会给慢模型带来自相矛盾的标签。后续生成世界时应让任务文字能区分目标（例如“站着的人”），或不放同样满足任务文字的干扰物。

所有确认都走“两个视角各投一票”。每架次调用慢系统 5–31 次；开发机上慢系统单次中位数约 0.5–1.7 s（与 Gazebo 共用 RTX 4060），快系统约 0.04–0.2 s。剩下的真实错误全部是慢模型对未见类别的身份判断（相近车型、红色牌子），主机闭环本身在这 12 架次里没有再出现跟丢、振荡或飞过头。

慢模型 v2-r4-prop（`eval-v2-test-r4prop`）：训练数据加入了机上快系统在训练世界画面上实际给出的候选框（按分割真值标注为目标 / 干扰物 / 场景物 / 空框），机上问单个候选时用约束解码只允许“接近 / 确认 / 拒绝”并固定焦点轨迹。加油站牌的误确认消失，成功架次定位误差全部在 0.29–0.57 m；剩下的真实误确认只有 w0037 的 SUV 被当成皮卡。w0034 的停车标志这次被提出来了，但慢模型给出“候选是红色停车标志；任务要红色停车标志”却仍然拒绝——测试目标类别在训练里只当过干扰物，模型学到了“这一类总是拒绝”的类别先验。下一版训练数据加入反事实任务（同一个干扰物在点名它的任务里是正样本），并让留出类在训练里完全不出现。

用录制数据离线回放新的地面锚定跟踪：w0036 同一次接近里的目标 ID 连续不断，w0035 目标 ID 数 11 → 2，w0037 两个车辆在 85 m 外全程保持各自 ID、地面定位误差约 2.5 m。

## 已知限制

- 小目标（停车标志）在巡航高度下检测器看不到，需要低空搜索或变焦策略。
- 慢模型会把相近类别（SUV / 皮卡）判混，近距离也一样；需要用真实候选中的难负样本继续训练。
- 部分世界的任务文字有歧义（见上），需要在世界生成器里修正。
- 只做了“找到并记录位置”一种技能；多用途任务合约（13 个技能）还没有接到闭环里。
- 全部数字来自 RTX 4060 上的 SIM；Jetson Orin 8GB 的延迟和内存还没实测。
