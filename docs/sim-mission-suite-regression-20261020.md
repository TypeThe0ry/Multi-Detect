# SIM 任务套件全量回归（2026-10-20）

用最新集成代码把 SIM 文本任务套件（`run_mission_suite.py`，r18 身份模型，x500，每类 1 架次）全部跑了一遍，用来检查这两天的改动（计数覆盖收尾、选焦点过滤、仿真时钟、EKF 仿真修复、llama-server 孤儿处理等）有没有把其他任务带坏。回归抓到 3 个真问题，修好后重跑。

## 回归中发现并修复的问题

| 问题 | 表现 | 修复 |
|---|---|---|
| llama-server 孤儿检查拼 PowerShell 命令时对含 `{ }` 的脚本用了 `str.format` | 机上策略每次启动都抛 `KeyError`，15 类里 12 类没飞起来 | `c53c390`，新增不打桩的回归测试 |
| SIM 地面事件时间线调用 `supervisor.evaluate()` 时没传飞机位置 | 有电池遥测后，能量模型“缺返航几何 → 立刻返航”，断链、无通信巡逻、人工中止、暂停/恢复 4 类都以错误原因返航 | `26417d8`：时间线传入当前位置；真机上“无位置就返航”的保守规则保留 |
| 计数记录里有 `set`（同框航迹）和外观 dataclass | 带监督器的计数（无通信计数）数到第一个物体就因日志 JSON 编码崩溃 | `258aa98`：日志编码把集合写成排序列表、dataclass 写成对象 |

另外，人工中止场景第一次重跑时，监督器在中止指令前就以“连续低置信身份判断”返航：三次慢模型调用没有给出判断，但日志里只记了空值，分不清是服务端出错还是答案解析失败。现在会记录 `perception_error` 及原因（`3a636ed`）；再次重跑时没有出现空判断，中止按预期生效。
