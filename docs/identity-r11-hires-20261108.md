# r11：提高训练输入分辨率

候选维持 r10 已审计数据与 r3 热启动，训练最长边从 448 提高至 672，显式使用 BF16。
672 对应最大像素预算 451,584（原 200,704）；最大输入 token 从 2,048 调至 4,096，
防止双图候选裁剪提示截断。其余训练参数保持 1 epoch、LoRA rank 16 / alpha 32、
学习率 5e-5、梯度累积 4、`candidate_zoom_v2`。每 25 步保存可恢复 checkpoint。

仅 GPU1；systemd cgroup 强制 `MemoryMax=64G`、`MemorySwapMax=0`，
CUDA allocator 预算 88%。不改现役配置。训练不新增样本，按文本及 ID 检查与冻结
planning-v5 的 126 题和返航探测 15 题无交集，并记录文件 SHA256；重启前校验一致性。
普通规划 replay 原有 1,500 行，不属于这两组冻结评测。

完整作业入口 `scripts/queue_r21id_round_r11.sh`：训练→导出→v1/v3→冻结四视角→r9r val，
先跑默认 448 推理，与现役 r3 可直接比较。提高训练分辨率本身不构成准入；仍需
`<12px` recall 相对 r3 提高至少 10 pp、其它指标不退步，及四视角与泛化门槛。
若需要 672 推理，必须补做 r3/r11 同分辨率成对评测并核对机载预算，不能拿不同
推理分辨率的数值直接替换默认 448 基线。

已有 r31 产物显示 planning-v5 97/126、返航 15/15；旧准入器仍因 v3/v4 回退拒绝。
本轮不改规划模型选择；应以当前集成 HEAD 重评冻结集合并向主协调者提交门槛差异。
