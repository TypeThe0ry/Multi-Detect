# r21id-r9r 双方向拒绝世界准备计划（2026-11-06）

## 范围

r9r 生成 48 个新世界：`car→mailbox` 与 `suv→postbox` 各 24 个。每个方向按世界划分 18 train / 6 val；同一世界的视角与 episode 不跨 split。每世界计划采集 2 个 `--teacher-target confuser` episode，路线围绕 confuser 的 `front`、`oblique`、`edge_truncated`、`recovery` 四视角执行。

本轮先采集 **pilot：每个配对方向 4 个 world，共 8 个 world**。两个方向分别检查拒绝门槛，只有 `car→mailbox` 和 `suv→postbox` 都达到“总量至少 96，且四视角各至少 8”的门槛，才采集剩余 40 个 world。未通过时只调整对应方向，不启动全量采集。

## recovery 根因与修复

r9q 已有 128 张 geometry-qualified recovery RGB。它们证明 mailbox-centered teacher route 实际进入 recovery，不能解释为“没有 recovery 帧”。按已有 builder 输出与原始 step 标签对齐后，`car→mailbox` 的 identity positive 在 recovery 有 4 张，但 rejection 为 `21 / 6 / 3 / 0`（front / oblique / edge_truncated / recovery）。

原因在 builder 的 hard-negative pairing：每个 confusable pair 历史上共享一个全局 30 行上限。前 30 个 `car→mailbox` pair 已由前三个视角消耗，recovery 即使存在同帧 true-car positive，也没有机会生成 paired rejection。r9q 的旧 sidecar 还只把 confuser 路线放在 `confuser_observation`，所以旧 builder 输出的 `view` 为空；r9r 生成器将 confuser 路线同步写入 `observation`，builder 可据此正确派生 recovery。

builder 新增可选 `--confusable-negative-view-cap`；`profile: r21id-r9r` 即使不传参数也自动使用 `30`，显式传参可让运行回执记录意图。其他 profile 继续使用历史全局 cap 和行集合。每个 pair 在每个 derived view 独立计数，避免 recovery 被前视角耗尽。

## 只能由 r9q 现有帧支持的估计

现有 r9q 4-world、8-episode 证据可支持：geometry-qualified RGB 为 540，四视角为 `156 / 128 / 128 / 128`；`car→mailbox` 最终 rejection 为 30，视角为 `21 / 6 / 3 / 0`。按这组数据机械外推到同样 48-world 配额，约为 360 条 rejection，视角约 `252 / 72 / 36 / 0`，仍不能通过 recovery 门槛。

这只是旧全局 cap 的算术外推，不能估计 r9r 启用 per-view cap 后的 rejection 数，也不能把 geometry-qualified RGB 当成 proposal 命中或最终 paired reject。pilot 之外的新背景、遮挡、YOLOE proposal 覆盖、RGB 去重和 builder 行冲突，只能在实际 pilot 运行后知道。

## 几何门槛

生成器对每个 world、每个 confuser 视角调用 `project_target_bbox` 预测 truth bbox 短边；任何视角低于 8 px 都使生成失败。当前 r9r 生成结果的四视角均声明每视角 8 帧，mesh scale 为 `1 1 1`，并保留 catalog 源尺寸。该 CPU 投影只验证路线/几何可见性，不代表实际 RGB、YOLOE proposal 或 SFT builder 标签。

## Pilot 采集命令

先由操作者从已生成的 `index.json` 写出临时 pilot index，只保留每个方向的 `w0000`–`w0003`；临时文件放在 `.tmp`，不写 `artifacts/`。示例：

```bash
export PYTHONPATH=src:. PYTHONUTF8=1 TMPDIR=$PWD/.tmp
python - <<'PY'
import json
from pathlib import Path
src = Path("configs/scenarios/generated-r21id-r9r/index.json")
dst = Path(".tmp/r9r-pilot-index.json")
doc = json.loads(src.read_text(encoding="utf-8"))
keep = [row for row in doc["worlds"] if int(row["world_id"][-4:]) % 24 < 4]
assert len(keep) == 8
doc["worlds"] = keep
dst.parent.mkdir(parents=True, exist_ok=True)
dst.write_text(json.dumps(doc, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
PY
/data/projects/Multi-Detect-env/Multi-Detect/.venv/bin/python \
  scripts/run_r15_round.py \
  --stage collect \
  --out artifacts/r21id-r9r-pilot \
  --scenarios configs/scenarios/generated-r21id-r9r \
  --r15-index .tmp/r9r-pilot-index.json \
  --episodes-per-world 2 \
  --teacher-target confuser
```

采集后按方向分别运行 proposal cache 与 builder，并传 `--confusable-negative-view-cap 30`。先按 RGB 内容哈希去重，再检查每个方向的总量和四视角门槛；不能把另一方向的正样本或 geometry 代理计入本方向 rejection。

## 扩展 40 个 world

pilot 两个方向都通过后，生成一个排除上述 8 个 world 的临时 index，采集剩余 40 个 world，仍为每 world 2 个 confuser episode。扩展阶段沿用相同的 builder 参数和方向内 gate；任一方向未通过就暂停该方向，保留已完成 pilot 证据。

本次只准备 world、builder 参数、测试和 onboard gate，不启动 collection、SITL、Docker、GPU annotate 或训练。
