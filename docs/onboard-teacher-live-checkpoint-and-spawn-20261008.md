# 实时任务准入与 Gazebo 出生高度对照

最终目标仍是：用户说清任务后，机载 AI 根据实际画面、状态和记忆决定下一步行动，
执行后再观察并调整。本轮为动作训练补执行数据的前置条件；教师路线是采集工具，
不是把用户任务固定写成剧本。没有新增训练，也没有自主起飞验收。

## 取得的实际结果

三个子智能体分别负责实时观测、执行前重验证和机体几何；主线程负责整合、测试、
真实模拟实验、公开模型复查和仓库进度。使用实际 PX4/Gazebo 三维场景，不是 Python
轨迹夹具或世界模型生成的视频。

原出生位置的落脚点与垫面存在约 **6.44 厘米**几何重叠。新实验保留同一地图、种子
和故障配置，仅增加显式初始位置：模型在地面上方 **15 厘米**出生，让未解锁飞机
自然落稳。新的真实运行成功退出，保存 **4 帧 RGB、4 份深度、5,222 条原始遥测**。

落稳后，模型高度约 **0.0669998165 米**，机体参考点约 **0.3069998165 米**。
从实际碰撞体重算的最低落脚点约 **0.0799998139 米**；垫面为 0.08 米，两者差
约 **−0.186 微米**。四帧原始相机位姿也与稳定位置一致。实际场景导出在相机之后，
不称精确同期。容器与监督器自有进程树均已清理，另一次精确容器查询也确认不存在。

飞机保持静止，四份 RGB 和四份深度的各自 payload 哈希相同；它们是不同采集时刻，
不是四种场景或有动作后继的训练样本，不扩算数据多样性。

结果支持“原出生位置初始穿入”的解释，但没有测量接触力或核验实际物理引擎后端。
成功采集、几何兼容、实时准入和允许飞行是不同结论。默认场景未替换；变体不算新
未见世界，不改变数据分组。

第一次尝试在启动前被哈希检查拒绝：新清单错用了原始文件哈希，加载器要求规范化
JSON 哈希。错误输出和原清单已保存；修正后补实际加载器回归，再用新 R2 目录运行。
不把两次尝试合并成一次成功。

## 原计划与当前状态分角色

上传和读回需要时间。原计划保留生成时的观测、任务、路线和授权身份，不能为了启动
把旧时间改成现在；控制前另取真实最新观测。

- 原计划证明：经过审查的任务、路线、原始观测、预算、环境和授权身份。
- 当前执行检查：在切换 Mission 模式和正常解锁前，重新核对原始报文、实际相机、
  当前容器、导航参考／重置连续性、电量和整条路线。

新开发接口只读取同一通信线程已落盘的完整提交部分。日志可继续追加，但不能改写
此前内容、换文件或截断；无需关闭会话后把历史文件冒称实时。接收时间、传感器时间
和检查时间分别保留。配置风来自绑定的 SDF，历史 runtime 的北／东声明差异另记，
不把配置说成测得风力或已验证气动力。

执行接线复用已有上传、回读、提交、许可和唯一通信线程，仅支持原有有限控制。
正常解锁的 force 参数为 0，未知投递超时不自动重试。新检查不生成 PASS／Grant。
本轮只有新接口的 CPU 验证，尚未在真实运行中用新准入解锁。

## 不继续把旧检查当物理定律

环境接口重读 Gazebo 实际加载原件，与仓库静态场景核对，提供碰撞体库存及有覆盖
范围的地面／静态高度上界。两处建筑的上界分别为 14 米、20 米；地面外不外推。
它是安全监督输入，不给 Actor 偷看世界真值，不将静态模型叫实测 DEM，也不擅自
把旧资源标志改成健康。旧无条件地图／DEM门仍需显式能力契约整合，不能只绕过检查。

机体包络从完整三模型合并链、九个实际碰撞体和四个旋翼扫掠重算。空中默认覆盖任意
姿态；较小倾斜域只是设计假设，未证明飞控实际遵守。地面必须用实际姿态、足点和
支撑几何，不把任意姿态球形包络直接套到落地接触。

旧接触检查拒绝超过 1 纳米的任何负间隙，容差只允许正间隙，因此仍拒绝本次约
0.186 微米残差。新 signed 几何契约明确预声明 **1 微米数值穿入／1 毫米正间隙**，
把源定义下的几何兼容与实时落地状态、接触力、求解器行为分开。这个数值域是显式
工程声明，不能从 SDF 的 ODE 字段擅自推为实际引擎容差，更不能掩盖原 6.44 厘米重叠。
它不单独批准起飞或完整路线。

独立复审还发现执行线程会误调用只属于主线程的日志检查接口。这个缺陷未被首轮
单元测试覆盖；已分开当前主线程准入与发送线程只读重算，补实际不同线程、不同资格
时刻和延迟回归，不放松日志所有权。发送租约同时绑定准确双提交批次；若其后已
提交新遥测，就拒绝复用旧观测，要求重新采集。未收到／未提交的变化仍不能声称已发现。

旧精确 V3 传输写入器还有 8,192 包上限，两个旧执行意图均最长 60 秒，不能默认支撑
完整教师架次。后续需在起飞前明确覆盖检查、上传与读回、执行、返航降落、清理的
总时间，以及报文、字节、队列、落盘和收尾预算；不能只增缓存或续旧意图。

## 公开模型复查和接下来做什么

本机重新读取的显卡是 RTX 4060、8GB 显存，不按历史口述的 4060 Ti 估算。本轮
重新浏览官方发布页面，未下载或加载新权重：

- [OpenFly](https://github.com/SHAILAB-IPEC/OpenFly-Platform)可作航空动作对照，但仍须
  核输出语义、基础许可、量化容量和 PX4 适配；[官方权重卡](https://huggingface.co/IPEC-COMMUNITY/openfly-agent-7b)。
- [MiniCPM-RobotManip](https://huggingface.co/openbmb/MiniCPM-RobotManip)有图文／状态到
  动作和历史记忆接口，是机械操作模型，不是现成无人机驾驶员。
- [MolmoAct2](https://github.com/allenai/molmoact2)的连续动作与训练链可研究为辅助教师，
  目标机型和飞行动作仍需独立适配。

补查[Cosmos3-Edge 官方模型卡](https://huggingface.co/nvidia/Cosmos3-Edge)：4B，除视觉
理解外有动作条件生成，许可标为 OpenMDW-1.1；兼容动作列表含相机运动、汽车和
机械操作，没有 PX4 无人机。可列为离线预测／辅助教师候选，不直接接管飞行。

不能把“Edge”或“Jetson”名称当本机已验容量。官方[嵌入式基准](https://github.com/NVIDIA/cosmos/blob/main/inference_benchmarks.md)
里的 Orin 是 **AGX Orin 64GB**，该 eager 视觉推理测试约 10.8 秒；不是 Orin Nano
或 RTX 4060 8GB 的结果，也不是动作控制周期。量化容量和飞行适配本轮未验证。
因此当前判断仍是先补真实执行数据，小模型与航空动作对照继续；世界模型作为独立
实验支路。生成画面不作实际坐标、碰撞、ACK 或飞行标签。

优先闭合短教师架次的真实准入、接触几何、完整路线和有限资源预算，取得命令、ACK、
实际运动、后继画面与失败恢复数据。审核后再做有界三维动作微调：原底座、旧 warm、
新候选使用相同输入公平比较，按完整 episode／场景隔离；生成视频不替代真实回流。

默认仍为 r33，版本仍为 `0.3.0-pre.8`。新开发入口未写入旧 canonical 部署；本轮
未通过实际起飞、模型晋升、Jetson、HIL／REAL、室外 GNSS 或最终 0.3.0。
来源、原件与验证范围见[本轮证据](evidence/onboard-teacher-live-checkpoint-and-spawn-20261008-r1.json)。
