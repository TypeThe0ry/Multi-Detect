# 下一轮训练要补什么能力

目标不是让模型熟记几条路线，而是让它根据用户任务、当前画面和刚才发生的事，决定
下一步飞向哪里；执行后继续观察，遇到受阻、目标丢失或任务变化时调整，最终汇报结果。
原模型或架构都可以更换，但训练、模拟与部署必须明确用的是哪套模型和行动接口。

## 先把真实数据链跑通

更新：候选已完成8帧实际推理，但全STOP；[CPU诊断](onboard-navigation-head-diagnostics-20261008.md)
不能将原因归为恒定偏置。新的[执行反馈合同及原文件核验](onboard-executed-trajectory-data-20261008.md)
已经实现，107合同／33集成测试通过；还没有新teacher飞行轨迹，不把软件fixture算训练样本。

2026-10-08 已从真正 Gazebo 三维场景采集 8 张原始相机画面、配对深度和来源姿态，
并通过共享导航输入。它们来自地面观察，没有飞行、模型决定或专家动作标签；
不能直接说成“8条自主飞行训练样本”。实际结果见[相机接线](onboard-navigation-gazebo-shadow-20261008.md)。

下一轮先做有界教师轨迹：保留教师原始提议、通过安全检查的动作、实际执行事件、
执行后的真实画面与结果。提议、执行和成功是三件事；受阻、拒绝、超时和恢复失败
也要记录。教师是训练时提供示范的工具，不是部署时按用户一句话查表的固定策略。

## 数据与输出一起扩展

- 不再只有固定前进3米与转30度：加入不同距离、不同转角、上升、下降、横移、后退、
  障碍前缩短步长、绕行和受阻后恢复。
- 同一个观察位置提出真正不同的任务，让教师基于各自目标重新规划；只改同义句
  不算任务反事实。相同画面的所有变体留在同一个数据分组，防止测试泄漏。
- 当前四类动作头不能表达三维平移，必须新建覆盖这些动作的学习输出；现有行动
  接口可表示三维位移，无需为保护旧四类输出而把上升、横移硬塞成“前进”。
- 临时等待、因受阻停下、序列结束、任务完成和返航分别记录，不把它们全部标成STOP。

只靠图像中某个框的深度不能证明整条路线安全。教师采集仍复用已有安全准入与PX4
执行路径；没有完整净空证据时不补造通过。姿态必须包含完整旋转信息，不能只用
水平航向推算上升和横移；计划动作和真实位移也不能互相冒充。

## 用新场景检验，而不是重复熟悉场景

采集前锁定训练、开发与最终未见世界。相同地图换随机种子、出生点或路线不能叫
未见场景；同地图换文件名也不能隔离测试。最终世界在模型和预算确定后才首次评估。
旧86、已观察59和本轮208都不能重新变成“从未看过的最终测试”。

连续改进路线是保留当前小VLM、替换动作输出并补真实多任务三维数据；迁移较小，
但尚无合格导航质量证据。替换路线是比较公开小VLA或世界模型作为候选／离线教师，
仍需航空动作适配、真实数据、时延和未见场景验证。先公平比较原始底座、旧warm和
候选的相同输入，再决定保留、局部改造或更换；不用论文成绩或已有代码投入替代判断。

## 进入下一步的顺序

真实相机来源闭合 → 精确模型只观察推理 → 公平对照 → 教师采集计划与数据契约 →
有界多任务采集与训练 → 未见世界闭环 → 合格后的受监督飞行 → Jetson／硬件验证。

模型只接用户原文、当前／过去画面；未来帧、目标真值、教师动作、位置答案、深度和
来源信息保留在单独训练证据里，不偷偷加入Actor。新的真实轨迹采用独立来源版本，
不能伪装成旧的预计划位姿监督。每轮预算、失败和模型身份分别保留，不重置旧消耗。
