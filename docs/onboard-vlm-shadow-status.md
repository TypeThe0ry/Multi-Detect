# OnboardAI 图像、任务与记忆接入

> 后续进度：已执行一轮 26 次真实 LoRA 更新及 84/84 配对生成；格式改善但遮挡／目标
> 指代仍有回归，原生任务在 adapter 重新加载验证失败退出 1；独立正确重载已实测退出 0，
> 参数及固定验证生成一致，原报告不改写，不晋升。见
> [训练结果](onboard-vlm-grounding-training.md)。以下八用例记录保留为训练前历史，不改写。

这条开发分支要让模型真正看到画面、读到用户的任务，并根据连续观察提出下一步，而不是只
把预先写好的事件表换一个名字。最终仍是同一套 OnboardAI 在模拟和 Jetson 上运行：模型负责
判断，现有检测、跟踪、测距、定位和 PX4 执行链继续提供真实观测与执行能力。

## 这轮实现了什么

- 共享输入包含原始 Prompt、实际 RGB 字节、图像身份、采样时间和历史帧；缺失的 GPS、HOME、
  电量和姿态明确为未知，不补默认飞机状态。
- 执行记忆区分“模型提出”“执行器接受”“实际执行”“完成记录”。模型的自述不能写成完成
  记录；真实执行证据还需要采集端确认来源，文件哈希只能证明字节身份，不能证明事件发生。
- 使用官方公开的 `Qwen/Qwen3-VL-2B-Instruct`，固定 revision
  `89644892e4d85e24eaac8bacfd4f463576704203`。新 `.venv-vlm` 与原训练环境分离，模型与缓存在
  D 盘；没有升级原 `.venv-train`，没有改动当前 r33 引用或原 COCO 检测器。
- 用例从已登记的实体 SDF 三维场景的 Blender RGB 中选取，只用原 train 分区，比较同图不同
  任务、同任务不同历史。它们不是盲测，也不是 Gazebo 相机本轮采集，更没有预写飞行答案。
- 模型输出必须原样经过严格结构化意图校验；未知字段、虚构证据、过期结果、越界数值和
  没有观测注册表支持的目标 ID 都不能通过。原始输出与拒绝原因保留，不修补 JSON 冒充成功。

独立审查已修正两处实际输入问题：历史帧必须全部有同一录制身份，且录制身份参与输入哈希；
模型可见的帧与任务 ID 改为无语义标识，不让“遮挡/重现”等用例名字暗示答案。评估标签即使
被改写，模型输入和消息仍完全不变。源名称、完整输入及标注来源只用于模型之外的审计。

## 本机实际运行结果（2026-10-07）

RTX 4060 8GB 已完成一次加载、8 个用例的实际 CUDA 生成，进程退出码为 0。独立审查重新
解析原始字节，确认 7 个回答满足结构，1 个把 `record_location` 错放进 `response` 被拒绝。
7 个结构合格回答全部为 `hold`，全部 8 个回答的任务动作和飞行计划均为空。因此它证明了
图像、任务与历史能进入共享模型接口，不证明模型已经生成或执行了自主飞行计划。

| 本机实测 | 结果 |
| --- | ---: |
| 模型加载 | 5.44 秒 |
| 单帧完整回答 | 8.43–13.69 秒 |
| 4 帧历史完整回答 | 14.72 秒 |
| 6 帧历史完整回答 | 19.82 秒 |
| 峰值模型 allocated 显存 | 5.403 GiB |
| 峰值 reserved 显存 | 5.832 GiB |

输出为264–403 tokens，均正常结束，没有触及512上限；真实图像也没有因8192输入token
上限被截掉。30秒只是这一离线基线的预算，不是生产实时飞行标准。

语义检验失败是本轮重要结果：4帧回答说目标连续可见；6帧回答说紫色低矮实体全程可见、
位置没变，还在没有遥测时声称飞机没有运动。实际近景序列的目标可见像素为
2521→1818→174→0→91→2133，包含完全遮挡和重现。自报0.95置信度不证明这些判断正确。
这些 mask 仅由离线审查读取，从未传给模型。当前不能据此晋升候选、称历史推理通过，
更不能启用实时飞行；后续需要针对事实判断与时延训练和验证。

保留[持久结果回执](evidence/onboard-vlm-native-shadow-20261007-r1.json)、
[完整原生报告](../artifacts/evaluation/onboard-vlm-qwen3vl-native-probe-20261007-r1/report.json)
及每个用例的原始回答。独立审查重算179条分组绑定、148个唯一文件，重新解码token与复核
图像；合同接受率没有被当成任务准确率。

## 怎样看待这次推理

这是没有飞控输出的开发旁路测试。它回答“预训练模型实际读了什么、输出了什么、结构是否
合格、需要多少显存和时间”，不回答“无人机已经能自主完成任务”。这些用例没有可用的同帧
飞行上下文，因此不会据此编译或发送移动 Mission，更不会凭模型文字生成米制距离或 GPS。

离线测试用自己的明确时轴：保留源 clip 的帧时间，将本机实测耗时加到最后观察的时间上。
离线推理预算与允许的帧年龄一并保存，不冒充在线传感器时间，也不代表生产实时门已经通过。
生成器的软时间上限和返回后拒绝迟到输出，不等于独立安全循环所需的硬取消能力。

同图不同任务出现不同文字，只能作为任务敏感性线索；历史帧出现不同描述，也不等于已学会
持续任务记忆。需要独立审核视觉事实、扰动对照、更多未见场景和实际连续飞行验证。

## 下一步如何训练

先从本轮真实输出中找出可复现的缺陷：看错实体、遗漏遮挡、编造未知位置、忘记已执行步骤，
以及结构化输出不稳定。训练样本必须有对应 RGB、任务文本和可核对的事实/执行记录；没有
动作证据的画面只能用于视觉或语义训练，不能自动变成“往左飞十米”的正确动作标签。

之后对预训练模型做有监督增量微调，或将有用能力蒸馏到已有轻量策略。r33 仍是可比较的
原模型；不能声称其小型网络参数直接迁移进架构不同的 VLM。比较候选时同时看任务质量、
幻觉、时延、内存和跨场景表现，不因一次输出漂亮就替换当前模型。

最近一步是按整个clip/场景隔离，补一批独立审核的图文窗口：明确目标指代、可见→遮挡→
重现、同图不同Prompt、不能从画面确定飞机速度/GPS等反例，再尝试小adapter/LoRA的真实
backward显存预检。100–300个窗口可作为开发起点，不是充分数据的保证；本轮8用例没有
动作gold，不直接当专家演示。动作策略微调仍需要同步真实状态、执行记录和审核任务轨迹。
另可将请求hash关联移到host，减少让模型抄长字符串的输出成本；仍须保存原始JSON，验证
请求身份、scope、引用与deadline，并实测对照，不能以补字段的方式修答。

世界模型另有明确角色：先评估小型 V-JEPA 视频编码器是否帮助观察历史表征，再考虑有动作
条件的预测。机器人或游戏上已有权重，不等于 PX4 无人机动力学权重；世界模型研究和这次
VLM 实际推理也分别记账。[官方候选研究](research/onboard-world-model-candidates-20261007.md)
保留了可用权重、资源与适用范围。

最终接入还需要：有真实上下文的规划重验、独立慢推理 worker 与硬取消、实际 Gazebo/PX4
连续任务闭环、Jetson 性能测量，以及后续 HIL/REAL 验收。本轮不会晋升候选或发布最终 0.3.0。
