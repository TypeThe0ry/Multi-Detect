# Gazebo 自主训练：查清飞控输入与缺失量值

本轮实际推进的是自主训练的前置闭环，不是新的训练成功。三个子智能体分别完成
事件解码、只读参数连接和独立审核，主线程完成实际 PX4/Gazebo 查询、原包复算及整合。
版本仍是 `0.3.0-pre.8`，当前默认 r33 模型没有替换；原训练与失败实验保留。

## 已经知道什么

实际运行中的 PX4 报告版本 `1.18.0 80 (17956992)`、固件 hash
`83c4f4e580558816f0e398918f66358988004696`。这次只读运行保存了 4,623 条原始遥测，
没有 orphan 或队列溢出。接收与发送使用同一个连接、同一个 RX 线程，日志只由主线程写。
停止接收、排空队列、封存之后，才对自己创建的容器读取版本、18 项参数和日志。

| 实际观察 | 对自主任务的意义 |
|---|---|
| `COM_RC_IN_MODE=1` | 固定镜像自己的定义说明它选择 MAVLink 手动输入，不等于无人手动输入模式。当前只读连接没有提供这种输入。 |
| `BAT1_CAPACITY=-1` | 容量尚未配置成已知量，不能把飞控没有提供的剩余时间补成正数。 |
| `BAT_AVRG_CURRENT=15` | 它是实际配置值，不等于电流传感器实测或该飞机的物理标定。 |
| `NAV_RCL_ACT=2`、`NAV_DLL_ACT=2` | 现有失联策略选择返航；本轮没有关闭它们，也没有更改参数。 |
| `BAT1_A_PER_V` 没有响应 | 保持缺失。原生 `px4-param show` 退出 0 也不证明该参数存在。 |

收到的 AUTOPILOT_VERSION capabilities 为 59,647，只声明 bytewise 参数编码。
新的离线工具检查整份 journal、每条记录的原始标签和 header，再对版本与参数包核 CRC、
来源 ID 和序号。从原四字节 union 解释 17 个参数，不从 tiny float／NaN 猜整数。
校验码不是来源认证；消息出现在请求后也不独立证明请求的因果响应。

此前 R3 的 24 个原 UNKNOWN 包现在也已另行离线校验：16 个事件与固定镜像的实际
metadata 匹配，其中两条是“没有手动输入”；另有 GCS、任务和位置检查提示。原包、
原 UNKNOWN 分类和 `source_accepted=false` 没有改。这些事件来自此前的 R3，不能
拼成这次参数运行中的同时状态，也不能据此宣布唯一根因或预飞通过。

## 这次仍然失败在哪里

版本和参数的 19 次原生读取都退出 0，原输出已保存；第 20 次容器日志读取虽然原生
退出 0，但输出超过 256 KiB 诊断上限，被拒绝。整轮 root／child 仍退出 1、状态为
`diagnostics-failed`。超限日志没有持久化，原大小也没有记录；不能说完整日志已审计。
后续日志入口需按字节有界保留原始前缀、明确完整／截断／失败状态，不能仅靠行数。

容器已按自己的 ID／标签清理，随后原生 inspect 确认不存在；两个自有 PID 也已独立
确认不存在，watchdog 未触发。40 项来源在执行窗口内前后相同。参数 consumer 随后
独立审核修复并输出新 R2 派生报告，不能把更新后的文件冒充旧执行窗口的源版本。

另一次只提取 metadata 的容器从未启动：明确 `created`、零 StartedAt，复制原文件、
核对展开与最终 SHA 后移除。64 MiB XZ 解码失败原件与 128 MiB 成功原件分别保留；
这只证明固定镜像的构建 metadata，不是运行中的参数默认值或固件认证。

所有本轮软件组件共 249 个定向 CPU case；与既有采集及文档／parity合计393项通过。
Ruff、格式及版本／默认策略／parity原SHA核通过。没有 ARM、
Mission、模型加载、新优化器更新、候选晋升、Jetson／实机／室外验收或正式发布。
完整数字与原件绑定见[本轮证据](evidence/onboard-teacher-px4-diagnostics-20261008-r1.json)。

## 接下来如何让 AI 真正学会执行

1. 声明这次 SIM 是无人手动输入的自主任务环境，明确操作员、GCS 心跳、失联和接管契约。
   根据实际固件定义形成最小配置差异；不能靠关闭全部预飞检查让它起飞。
2. 重新审视旧观测要求。多旋翼没有空速计不是错误；记录“没有测量”，用明确来源的
   地面运动与保守能力规划。固定翼／VTOL 固定翼段的需求另行保留，不能混用地速和空速。
3. 为 SIM 明确能量模型与预算来源，区分配置、估计和实测，保留时间连续性及未知值。
   不能拿 VTOL 的旧数字冒充 x500 标定，也不能把 SIM 估计自动移到真实 Jetson 飞行。
4. 在实际三维环境中完成一次起飞后的多个合法动作，记录原图、姿态、实际移动、
   后继画面和失败恢复。这才是“往左／往右／接近／继续搜索”的行动训练数据。
5. 对现有基座、当前 adapter 和小型 VLA 使用相同输入、预算和未见场景公平比较；
   场景与 Prompt 要多样化，不把红车例子变成固定答案。通过后再接同一 OnboardAI 到 Jetson。

这里允许重构旧输入／特征契约，但不会把同名 40 维向量偷偷改语义、让旧模型吃零填充值。
任务判断和行动选择由学习模型承担；测量是否存在、真实飞控能否安全执行仍须如实验证。

## 公开模型的当前用途

- [SmolVLA 官方模型卡](https://huggingface.co/lerobot/smolvla_base)：图像、状态与语言输入，
  输出连续动作，适合作为小型动作模型的独立对照。它需要航空动作语义和真实飞行反馈
  微调；官方“单 GPU”说法不等于本机 8GB／Jetson 已通过。
- [WorldVLN 官方仓库](https://github.com/EmbodiedCity/WorldVLN.code)：参考持续任务会话、
  动作片段、执行和后继图像闭环；优先作为离线教师／方法候选，不把想象画面当真实反馈。
- [AeroVLA 官方仓库](https://github.com/XuPeng23/AeroVLA)：航空 VLA 候选，需独立核验完整
  底座依赖、动作坐标和部署链。没有在本机或 Jetson 验证到的能力不写成已经能飞。

本轮复查官方页面，没有下载新权重或升级现有环境。

## 只读工具

在仓库根目录使用。输出是 create-only，必须选择新路径；默认计划模式不启动模拟器。

```powershell
python scripts/run_onboard_teacher_px4_diagnostics.py --output-directory artifacts/diagnostics/NEW-diagnostic
```

真实执行应经 `supervise_onboard_teacher_px4_diagnostics.py` 的独立 Job／watchdog；当前
日志超限失败已知且保留，不将该入口描述为端到端已通过。离线工具分别为
`diagnose_onboard_teacher_px4_events.py` 与 `diagnose_onboard_teacher_px4_parameters.py`。
