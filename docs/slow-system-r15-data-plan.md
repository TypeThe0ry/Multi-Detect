# 慢模型下一轮（r15）数据方案

2026-10-16，基于 1,900 次真实飞行身份判断（`artifacts/benchmarks/flight-identity-eval-v1-r12.json`、`-r14fast.json`，输入与真值 `artifacts/datasets/flight-identity-eval-v1/test.jsonl`）逐样本对齐分析。

## 现在错在哪里

“目标被拒”（漏判）最多的组合：

| 任务 → 候选 | r12 | r14 |
|---|---:|---:|
| 背包 → 背包 | 46 | 24 |
| 停车牌 → 停车牌 | 14 | 8 |
| 交通锥 → 交通锥 | 11 | 13 |
| SUV → SUV | 10 | 2 |

“干扰物被当成目标”（误判）最多的组合：

| 任务 → 候选 | r12 | r14 |
|---|---:|---:|
| 皮卡 → SUV | 3 | 72 |
| 停车牌 → 隔离墩 | 13 | 36 |
| 交通锥 → 隔离墩 | 23 | 5 |
| 背包 → 电箱 | 9 | 9 |

r14 少漏判 36 次，但多误判 75 次，所以机上身份判断继续用 r12，r14 只用来编任务计划。

## “真背包被拒”的真正原因

- 46 次被拒的真背包**全部来自同一个场地世界（gen_cnt2_w0003）**，候选框在 1280×960 画面里只有约 10×13 像素。
- 也就是说，这主要是“候选太小、看不清”的问题，不是“模型不认识背包”。在这么小的裁剪上，模型说“不是”本身就不可信。
- 这也说明评测集在这一类上过于集中在一个世界，结论不能直接推广。

## 训练集的不平衡

r14 训练集里，背包正样本 81 条、拒例 230 条；消防栓 18 对 241；邮箱 38 对 226。r13 证明了“复制正样本”会让模型变得爱说“是”（干扰物拒绝 95% → 58%），所以下一轮不再复制。

## r15 做法

1. 补采真实的小背包正样本：多个世界、不同距离、方位、光照、背景，并记录同一物体从远（小框）到近（清晰）的连续画面。
2. 按候选框大小分层：小框（短边 ≤ 16 px）、中框、大框分别统计召回和拒绝，验收也分层看。
3. 补成对难反例的不同场景：背包↔电箱/纸箱/行人，皮卡↔SUV，停车牌↔隔离墩。
4. 同一物体多视角、多距离的样本保持同一身份标签（真实采集，不是复制）。
5. 推理侧（不增加模型调用）：小框上的“不是”不当作最终结论，改为“飞近再看一次”，可选开关、默认关闭，正在实现并用离线数据量化代价（见 `wt/smallreject`）。

补采需要真实 Gazebo 仿真，目前受 C: 盘空间限制（Docker 磁盘镜像在 C:）暂缓。

## 按候选框大小看（2026-10-16 补充）

同一份 1,900 条评测按候选框短边分层（`scripts/rescore_size_buckets.py`，只读已有结果、不推理）：

| 短边 | 样本 | r12 准确率 / 真目标召回 / 干扰物拒绝 | r14 准确率 / 真目标召回 / 干扰物拒绝 |
|---|---:|---|---|
| < 12 px | 350 | 80.9% / 70.9% / 94.0% | 87.1% / 84.4% / 90.7% |
| 12–16 px | 415 | 92.3% / 96.0% / 90.2% | 93.3% / 97.4% / 90.9% |
| 16–20 px | 389 | 97.7% / 97.6% / 97.7% | 86.9% / 97.6% / 78.6% |
| 20–32 px | 395 | 94.9% / 91.9% / 96.7% | 91.4% / 95.3% / 89.0% |
| ≥ 32 px | 351 | 97.7% / 97.5% / 98.0% | 95.2% / 98.5% / 90.5% |

r12 的问题几乎全在 12 px 以下（真目标召回 71%）；12–16 px 两者接近，16 px 以上 r12 明显更稳（r14 干扰物拒绝掉到 79–91%）。所以 r15 的重点是“极小候选”，验收必须分层看，不能只看总分。今后每次评测输出都会自带这张分层表。
