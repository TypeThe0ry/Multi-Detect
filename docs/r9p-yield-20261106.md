# r21id-r9p 产出审计（2026-11-06）

本审计只读 `artifacts/r21id-r9pa`、r9p 的 round-state、truth、teacher intent 和 SDF。CPU 阶段没有启动 SITL、Docker、GPU、训练或联网，也没有写入 `artifacts/`。审计脚本为 `scripts/audit_r21id_r9p_yield.py`；可复现输出写在 `.tmp/r9p-audit/`。

## 结论与 48-world 建议

建议为 **adjust（当前不要直接 go 扩到 48 worlds）**。

- `car→mailbox`：r9p 的 3 个 complete episode 产生 **0 张** truth geometry 合格的独立 RGB；r8 也是 0。mailbox 在实际记录中的投影短边只有 **1.40–7.46 px**，低于 builder 的 8 px 下限。按 30 worlds × 2 episodes 推算仍为 **0**，不能通过 ≥96 张且每视角 ≥8 张的拒绝帧门槛。
- `suv→postbox`：r9p 的 3 个 complete episode 产生 **192 张** truth geometry 合格独立 RGB，四视角为 **25/82/21/64**；r8 为 44 张。按 18 worlds × 2 episodes 推算约 **2,304 张**（四视角约 **300/984/252/768**），CPU 几何上明显超过门槛。
- 上述数字是 truth 几何代理，不是 YOLOE proposal 命中，也不是 builder 最终标签。GPU annotate 仍需运行所附脚本验证 proposal 覆盖和最终 paired reject 行。
- 可以保留 SUV→postbox 的扩展方向；mailbox 方向应先改资产尺寸/朝向和 confuser-centered teacher route，再做小 pilot。当前 48-world 配额不应原样执行。

这里的 proposal 口径是 30 个 car→mailbox world（60 episodes）和 18 个 suv→postbox world（36 episodes），每 world 两个 episode，共 96 episodes。门槛沿用 r8：方向内独立拒绝 RGB 总数至少 96，且 front、oblique、edge_truncated、recovery 各至少 8。

w0001 与 w0000 的 mailbox mesh 完全相同，w0002 与 w0003 的 postbox mesh 完全相同；对象数为 5、7、8，失败数量没有随对象数、mesh 尺寸或距离呈稳定趋势。w0003 对象最多且距离最短但仍有 5 个失败 artifact，而 w0000 同为 8 objects 且距离更远却 0 失败。失败原因是 PX4 仿真时钟停滞、sensor wire stream、pre-arm health 和 takeoff timeout，当前证据支持“基础设施/仿真运行不稳定”，不支持“world 内容触发”。

## GPU annotate / builder 运行准备

CPU 无法核验 YOLOE proposal 和最终 paired reject 标签。已提供可运行脚本 `scripts/run_r9p_gpu_annotate.py`，它只读取 `artifacts/r21id-r9pa/episodes` 和 r9p index，在新的输出目录写 `proposals.jsonl`、builder 输出和 `run.json`；若输出目录已存在会拒绝覆盖。示例：

```bash
export PYTHONPATH=src:. PYTHONUTF8=1 TMPDIR=$PWD/.tmp
/data/projects/Multi-Detect-env/Multi-Detect/.venv-vlm/bin/python \
  scripts/run_r9p_gpu_annotate.py \
  --output .tmp/r9p-gpu-annotate
```

默认使用 `cuda:0`、1280 输入和 `confidence=0.05`，权重路径默认是 `artifacts/experiments/yoloe-v3-onboard-1280/train/weights/best.pt`。预计 RTX 3080 20 GB 峰值约 6 GB 显存；r9pa 约 900 张 RGB，proposal cache 约 3–8 分钟，随后 CPU builder 约 2–5 分钟。脚本不会运行 SITL、Docker 或训练；若权重不存在，应由运行者传入 `--weights`，脚本不会联网下载。

GPU 结果需要重点核对：proposal 与 truth/segmentation 的 IoU、`car→mailbox` 是否仍为零、`suv→postbox` 是否在四视角都有 paired reject 行，以及按 RGB 内容哈希去重后的方向内总数和 view gate。只有这些结果完成后，才应决定扩大 48-world 采集。
