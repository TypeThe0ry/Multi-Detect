# OnboardAI：取得真实行动反馈，再训练自主判断

目标没有变：用户给出任务后，飞机结合当前图像、位置和已经执行的动作持续判断，完成任务并自行处理异常。预写航线不是 AI 能力，世界模型生成的视频也不是已经飞过的证据。

## 当前结果

Gazebo 已能提供三维 RGB、深度和 PX4 原始消息。现有候选 AI 曾实际读取新画面，但八次动作均为 STOP，尚不能宣称会搜索或飞行。原感知模型、r33 默认策略和失败候选保留；本轮没有新训练、晋升或发布。

本轮新增三个开发组件：

- 完整架次预算：从原始会话开始时刻算起，包含准备、上传、正常解锁、执行、返航降落和清理。原包、图像、证据和最终回执均有有限上限，不逐步重新计时。
- 原件账本：写文件前预留容量，写后核对字节、SHA 和文件身份；未知、替换或部分写入不能算合格来源或剩余容量。
- 当前输入复核：完整保留通信原包，对相关导航记录做有限选择和重算；静态地理参考与持续传感器状态分开处理，不刷新原时间，不隐藏 HOME 更新或复位。

主流程已有显式新旧接口隔离。无飞行探针只验证当前采集，不代表整架次执行或清理已受完整预算约束；旧会话清理的逐调用上限不能冒充新架次的总清理截止。地图、地形和起飞／驻留／返航／降落软件检查也已补上，但静态检查不等于动态避障，条件地面姿态也不等于 PX4 实际保证，执行许可仍未完成。

## 五次真实只观察实验

五轮均实际运行自有 PX4/Gazebo，不解锁。原包和当轮源码副本保留；父子进程退出码均为 1，拒绝就是拒绝。来源清单稳定、自有进程树退出和自有容器清理均已核验。

| 轮次 | 真实拒绝原因 | 处理 |
| --- | --- | --- |
| R1 | 当前消息超过 2 秒 | 等新原包，不改接收时间 |
| R2 | SDF 被错误绑定为 JSON 指针 | 改为完整 XML 字节来源 |
| R3 | HOME 在窗口内实际改变 | 等启动稳定，不手动固定 HOME、不删包 |
| R4 | 单次静态 GPS 参考被误要求持续刷新 | 静态参考单独核对，当前状态仍严格限时 |
| R5 | 复核结束时当前输入过期 | 优化实际路径并记录耗时，不延长寿命 |

R5 的 HOME 已稳定 5 秒，原件已采到；但有效期仅剩约 0.49 秒，后续复核约用 0.88 秒，最终正确拒绝。落盘结果只能用于历史诊断，不能重新当作当前状态。

## 模型与下一步

保留已有检测、跟踪和共享 PX4 执行路径，增加从图像及行动历史学习的任务判断。航空动作模型做离线对照，小型 VLA 借鉴动作头，视觉世界模型辅助历史表征；它们都不能代替实际动作、ACK 和后继画面。见[预训练模型复核](onboard-pretrained-action-research-20261008-r4.md)。本机是 RTX 4060 8GB，不是 4060 Ti；Jetson 仍须单独验收。

下一阶段依次完成：新入口真实预扣与时延验证 → 当前地图／整路／授权闭合 → 完整教师架次的发送／ACK／移动／后继 RGB／返航降落 → 样本审核及独立场景留出训练 → 自由 Prompt 与在线重规划 → Jetson／HIL／硬件／室外 GNSS。

教师动作只用于采数据，不冒充模型决策。当前没有新 Mission 上传、ARM、飞行或动作训练；版本仍为 `0.3.0-pre.8`，最终 `0.3.0` 尚未完成。
