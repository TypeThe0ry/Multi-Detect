# OnboardAI：在已有视觉模型上继续训练

更新日期：2026-10-07。产品仍为 `0.3.0-pre.8`，不是最终发布。

## 这一轮要解决什么

无人机要自行决定怎么飞，首先必须分清“现在看见了目标”和“现在没有证据确认目标”。
上一轮图文模型学会了更完整地回答，但完全遮挡时的误报增多。因此本轮沿用已经保存的
Qwen3-VL-2B adapter，补充实际三维渲染中的可见、完全遮挡和目标不在画面中的例子，
检验它能否改善判断，而不是仅让回答格式更整齐。

这里的图像是实体 SDF 场景的 Blender 渲染，不是本轮 Gazebo 飞行录像。红车、绿车不被
写成固定答案；这批数据监督的是目标参考与当前图像中的可见事实。

## 怎样判断训练有没有用

用同一组 84 个留出输入对比更新前后的实际模型。分别检查可见目标是否认对，以及没有
可见目标时是否停止误报；不能让总分改善掩盖其中一类或一个分区的退步。完整回答和
全字段正确数不得降低，至少要多认对一个零可见像素的例子。没有深度、GPS 或执行事实
支持的导航字段必须保持未知，不允许通过猜距离或坐标刷分。

已经重新加载保存的 adapter，实际参数、原始回答和 token 精确复现。独立子智能体
从原始输出、训练日志和保存张量复算，训练程序自己报告的“通过”不是唯一依据。
原生程序正常退出与质量门通过是两件事；即便质量通过，也不自动替换默认飞行模型。

源码及 parent 回归 111 项、独立审计器完整回归 82 项均通过。第一次回归因默认 C 临时
目录与原 recovery 的 D 存储要求冲突而失败；在新的 D 临时目录重跑通过，原失败 JUnit
保留。第一次实际审计遇到官方五字段 provenance 与通用三字段绑定不匹配；以专用严格
验证器修复并保留诊断副本，不改原模型／报告。见[完整终态与哈希](evidence/onboard-vlm-grounding-increment-20261007-r2.json)。

终态证据、进度索引和生产 parity 的 57 项回归也原生退出 0，无失败或跳过；本阶段三个
互不重叠的回归组共 250 项通过。真实模型质量门仍然失败，测试通过不改变这个结论。

## Gazebo 当前在哪里

远程诊断已经找到可实际查询 daemon 的 Docker 程序，并成功拉取固定摘要的 PX4/Gazebo
镜像。随后被动 RGB/depth 八帧采集实际退出 1，尚未取得合格八帧；失败任务的内层日志
没有被 Controller 收集，不能猜测失败原因。诊断重跑暂受远程 worker 离线／调度约束阻挡。
本地 Docker 停止日志明确记录磁盘空间不足；没有自动重启、搬迁或删除用户数据。

镜像下载成功不是 Gazebo 渲染、自动飞行或动作训练通过。实际诊断和旧失败证据保留。

## 从这一轮到用户想要的自动任务

真正的目标仍是：用户输入一次任务，无人机持续读实际图像和飞机状态，自己选择下一段
行动，执行后观察结果；目标不匹配就继续搜索，环境变化就重新判断，完成后记录、返航
并汇报。模拟与 Jetson 使用同一受审模型和执行路径。

下一批完整工作要接通实际 Gazebo 图像／状态、持续图文推理、单一飞控接收与写入通道、
传感器支持的完整航段净空、连续两次空中任务更新，以及独立的等待／返航监督器。然后
保存“观察 → 决策 → 实际执行 → 后续图像与轨迹”的因果数据，再做动作微调。不能把模型
提出的行动当作已执行行动，也不能把 Blender 相机移动当飞机飞行。

当前 r33 默认策略和原 COCO 检测不变。本轮不证明任意 Prompt 自主飞行、Gazebo 全任务、
Jetson 实时性、HIL、REAL、室外 GNSS 或最终 `0.3.0` 发布通过。
